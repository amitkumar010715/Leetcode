---

## 1. **Short Summary**

Given a binary string of even length, compute the **minimum changes required** to make it **"beautiful"**—i.e., partitionable into substrings each of **even length** and consisting of only `'0'`s or only `'1'`s. You may change any character.

---

## 2. **Constraints & Edge Cases**

**Constraints:**
- Length of `s` is up to `10^5`, so solution must be O(n).
- `s` always has even length (minimum 2).
- Each `s[i]` is `'0'` or `'1'`.

**Edge Cases:**
- All same: "0000" - already beautiful; 0 changes.
- Alternate: "1010" - most different; each pair needs 1 change.
- Chunked: Long runs: "00001111" - already beautiful or can minimize to two big blocks.
- Minimum length: "10" (or "01") — must make both the same.

---

## 3. **Optimal Algorithm Explanation**

### **Observation**

- A "beautiful" string is a concatenation of substrings, each of **even length** and **all same characters**.
- A **minimal partition** is when you partition `s` into substrings of consecutive equal characters, each of even length.

### **Key Insight**

No matter how we rearrange, the best we can do is **merge consecutive same-chars into as big even-length blocks as possible, possibly splitting at odd-lengths**.

But **at minimum**, if you consider the string in chunks of two (`s[0..1]`, `s[2..3]`, ...), each pair must be **same** (either "00" or "11"). If not, at least one change is necessary in the pair.

**Reason:**
- If we split `s` into pairs (since s.length is even), and each pair matches, the string is beautiful (partition into size-2 substrings).
- Otherwise, we must change one of the pair to match the other, which costs 1 per differing pair. It is **always optimal** to fix minimal-length pairs.

### **Algorithm (O(N))**

- Loop in steps of 2.
- For each pair `s[i], s[i+1]`:
  - If both equal: no change.
  - If differ: need 1 change (make both `s[i]` or `s[i+1]`).
- Sum up changes.

This gives the minimum cost, because merging into longer blocks is not possible unless runs are already there, and you can't avoid the pairwise mismatch cost.

---

## 4. **C++ Solution**

```cpp
class Solution {
public:
    int minChanges(string s) {
        int n = s.size();
        int changes = 0;
        for (int i = 0; i < n; i += 2) {
            if (s[i] != s[i+1]) changes++;
        }
        return changes;
    }
};
```

---

## 5. **Example Explained**

**Example: `s = "1001"`**

- Pairs: "10", "01"
- "10": not same → 1 change (to "11" or "00")
- "01": not same → 1 change (to "00" or "11")

So, we need **2 changes**.

- e.g., change `s[1]` to '1' and `s[3]` to '0', resulting in "1100" (now partition as "11|00").

**Answer: 2**

---

### **Thus, the minimal number of changes is simply the number of pairs with differing characters.**
