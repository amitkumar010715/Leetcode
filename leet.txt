## 1. **Short Summary**

You can assign each of the 26 lowercase letters to one of the 8 keys (2-9) on a keypad, any way you want. Each letter, on its assigned key, is typed by pressing the key the corresponding number of times (1st letter: 1 push, 2nd letter: 2 pushes, etc.).

**Task:** Given a word, find the _minimal total number of key presses_ required to type it, if you can freely assign which key maps to which letters.

---

## 2. **Constraints & Edge Cases**

- **Word length:** `1 <= word.length <= 1e5` -- Large input, so **O(N log N)** or better needed.
- **Only lowercase English letters** (`a`-`z`).
- **Each letter assigned to one key**; each key may hold any subset of letters; no letter repeats across keys.
- May assign **fewer than 8 keys** if fewer than 8 letters in the word; keys can have any number of letters.
- **Letters can have different frequencies** — assign more frequent letters to earlier (cheaper) positions.

**Edge Cases:**
- Word with all same letter.
- All letters unique.
- All letters with equal frequency.
- Less than or equal to 8 unique letters.

---

## 3. **Optimal Algorithm**

### **Insight**

You want to minimize the sum: For each occurrence of each letter, the number of presses * frequency.

- **Optimal mapping**: Assign the most frequent letters to the earliest ("cheapest") positions on the keys (positions 1, 2, ...) across all keys.

- **Steps**:
    1. Count frequencies of each letter in the `word`.
    2. Sort frequencies decreasingly.
    3. Distribute letters into an 8×N grid (N ≥ frequency of the busiest position), filling position 1 on all keys first, then position 2, etc.

    - Given the mapping, the i-th letter (in sorted frequency order) gets position `pos = (i / 8) + 1` on a key, and thus costs `freq * pos`.

### **Pseudocode**

```
1. Count letter frequencies.
2. Sort frequencies descending.
3. For i, f in enumerate(frequencies_sorted):
       pushes += f * (i // 8 + 1)
4. Return pushes
```

- This ensures that the 8 most frequent letters get the first, cheapest positions, next 8 the 2nd position, etc.

### **Complexity**
- Frequency count: **O(N)**
- Sort 26 elements: **O(1)** (since constant size)
- Accumulate total: **O(1)**
- ---> **O(N)**

## 4. **Clean C++ Solution**

```cpp
#include <vector>
#include <string>
#include <algorithm>

class Solution {
public:
    int minimumPushes(std::string word) {
        std::vector<int> freq(26, 0);
        for (char c : word) freq[c - 'a']++;
        
        // Only push non-zero frequencies to our vector
        std::vector<int> letters;
        for (int f : freq) if (f > 0) letters.push_back(f);
        
        // Sort in descending order of frequency
        std::sort(letters.begin(), letters.end(), std::greater<int>());
        
        int total = 0;
        for (int i = 0; i < letters.size(); ++i) {
            int pos = (i / 8) + 1; // positions: 1-indexed
            total += letters[i] * pos;
        }
        return total;
    }
};
```

## 5. **Example Explanation**

Let's use **Example 3**: `word = "aabbccddeeffgghhiiiiii"`

First count letters:

| Letter | Frequency |
|--------|-----------|
| a      |     2     |
| b      |     2     |
| c      |     2     |
| d      |     2     |
| e      |     2     |
| f      |     2     |
| g      |     2     |
| h      |     2     |
| i      |     6     |

Sorted by frequency (descending): `6 (i), 2 (a), 2 (b), 2 (c), 2 (d), 2 (e), 2 (f), 2 (g), 2 (h)`

Assign by cheapest positions:

| Position            | Letters | # keys (max: 8) |
|---------------------|---------|-----------------|
| Position 1 (cost 1) | i, a, b, c, d, e, f, g | 8 letters |
| Position 2 (cost 2) | h | 1 letter (9th)  |

- So mapping (in code):  
  - i=0: 'i' freq=6: cost = 6\*1 = 6  
  - i=1 to i=7: each freq=2, cost = 2\*1=2, total 2\*7=14  
  - i=8: 'h' freq=2, cost=2\*2=4

- **Sum:** 6 + 14 + 4 = **24**

---

### **Summary Table (for general mapping):**

If `k` = 8 keys, for sorted frequency array F[0...L-1],  
position for F[i] is `(i // 8) + 1`  
**Total = sum_over_i (F[i] * (i//8 + 1))**

---

## **Concise Takeaway**
Greedily assign the most frequent letters to the cheapest positions across all available keys — this is fair, optimal, and efficiently computes the answer.
