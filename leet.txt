Let's break down the solution step-by-step:

---

## 1. **Summary**

Find the shortest (minimum weight) path from node `0` to node `n-1` in a **directed, weighted graph** with labels on each node, such that **no path contains more than `k` consecutive identical characters** according to the concatenation of node labels along the path. If no such path exists, return `-1`.

---

## 2. **Constraints & Edge Cases**

- `n` and `edges.length` can be up to **5e4 (50,000)** → Need an *efficient* solution (ideally O(M log N) or O(MK log N), where M is total edges).
- Labels: Only lowercase English letters.
- Each edge: positive weight, directed.
- `k` up to 50 → Small enough to track as state info.
  
**Edge Cases:**
- No path from 0 to n-1.
- All nodes have same label, but `k` is too small for the path.
- Shortcuts/longer paths may be optimal based on the label runs and weights.

---

## 3. **Optimal Algorithm**

**Dijkstra's Algorithm** with an *augmented state*:
- Usual Dijkstra state: (total_weight, node)
- **Augment the state** to track:
    - Current consecutive identical label count (`cnt`)
    - Current label (`ch` or just use labels[node])
- **State**: (current_node, current_consecutive_count)

**Why needed?**
- Visiting a node with different consecutive run requirements may lead to different valid paths, so we need to track by (node, consecutive_run).

**Implementation Steps:**
1. **Represent the graph** as adjacency list (vector).
2. **Use a min-heap (priority queue)** for Dijkstra:  
   Each state is `(current_total_cost, curr_node, consecutive_length)`.
3. For each transition:
   - If the **next node's label == current node's label**:
      - Increase the run-length by 1.
      - If the run length exceeds `k`: **invalid, skip.**
   - If **different**:
      - Reset the run-length to 1.
   - Only proceed to state `(next, run_length)` if it's not already been reached with lower or equal cost.
4. At the end, the minimal cost to `(n-1, any valid run)` is the answer.
5. If unreachable, return `-1`.

**Space Complexity:** O(N*K) (since we keep a cost map or array for every (node, possible run length))

---

## 4. **C++ Solution**

```cpp
#include <vector>
#include <queue>
#include <string>
#include <limits>
using namespace std;

class Solution {
public:
    int shortestPath(vector<vector<int>>& edges, string labels, int k) {
        int n = labels.size();
        vector<vector<pair<int, int>>> graph(n);
        for (auto& e : edges) {
            graph[e[0]].emplace_back(e[1], e[2]);
        }
        
        // cost[node][run_length == consecutive count of labels[node]]
        vector<vector<int>> cost(n, vector<int>(k+2, numeric_limits<int>::max()));
        using T = tuple<int, int, int>; // (total_weight, node, consecutive_count)
        priority_queue<T, vector<T>, greater<T>> pq;
        
        cost[0][1] = 0;
        pq.emplace(0, 0, 1);
        
        while (!pq.empty()) {
            auto [curr_cost, u, cnt] = pq.top();
            pq.pop();
            if (u == n-1) return curr_cost;
            if (cost[u][cnt] < curr_cost) continue; // Already found better
            
            char curr_label = labels[u];
            for (auto& [v, w] : graph[u]) {
                char next_label = labels[v];
                int ncnt = (next_label == curr_label) ? (cnt + 1) : 1;
                if (ncnt > k) continue;
                if (cost[v][ncnt] > curr_cost + w) {
                    cost[v][ncnt] = curr_cost + w;
                    pq.emplace(curr_cost + w, v, ncnt);
                }
            }
        }
        return -1;
    }
};
```

**Notes:**
- `cost[node][run_length]` saves best cost for each state to avoid revisiting worse paths.
- Dijkstra guarantees minimal path.

## 5. **Example Walkthrough**

**Example 1:**

- `n = 3`  
- `edges = [[0,1,1],[1,2,1],[0,2,3]]`
- `labels = "aab"`
- `k = 1`

Graph:
- 0 ("a") → 1 ("a"), cost 1
- 1 ("a") → 2 ("b"), cost 1
- 0 ("a") → 2 ("b"), cost 3

Let’s evaluate paths:

- **0 → 2**: label path = "ab" → no consecutive > 1, valid, cost = 3
- **0 → 1 → 2**: label path = "aab" → "aa" is two 'a's, but `k=1` → This violates the constraint.

So **only valid path** is 0→2 with cost = 3.

**The code will explore:**
- Queue starts with (0, node=0, run_length=1)
- From 0: edge to 1, next label same, run=2 (violates k), **so not taken**
- From 0: edge to 2, diff label, run=1, allowed, cost=3, and reaches target.

Output: **3**
