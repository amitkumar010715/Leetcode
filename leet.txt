Let's tackle the **Pyramid Transition Matrix** problem step by step:

---

## 1. **Short Summary**

Given a starting row `bottom` and a set of allowed triangular "pyramid patterns", determine if you can stack blocks up, layer by layer (each layer one shorter than the last), so that every block placement matches some allowed pattern. If you can reach the top (a single block), **return `true`**; else, **return `false`**.

---

## 2. **Constraints & Edge Cases**

- **`bottom.length`**: 2 to 6 blocks (very manageable for DFS/backtracking).
- **`allowed.length`**: Up to 216 patterns (since there are 6*6*6 possible triples within the alphabet {A,B,C,D,E,F}).
- **`allowed` are unique**.
- **Characters**: Only 'A'-'F'.
- **Edge cases**:
    - Some (a, b) pairs may not be allowed to stack anything on them (dead ends).
    - It's possible to have no valid sequence, even if partial layers can be built.
    - Empty `allowed` means impossible unless `bottom` is of length 1.

---

## 3. **Optimal Algorithm & Approach**

### 🧩 **State:**
Each layer is a string (or vector<char>). For every *pair* of adjacent blocks `(a, b)` in a layer, you must stack an allowed block `c` (so, (`a`, `b`, `c`) is allowed).

### 🔁 **Recursive Solution:**
*At each layer*, try **all possible choices** for stacking above each adjacent pair—**backtrack** if you hit a dead end.

#### **Steps:**
1. **Preprocess** allowed patterns into a map: `pair<string, vector<char>>`, mapping a 2-character base "AB" to all possible "C" that can be stacked above ("ABC" is allowed).
2. **DFS/backtracking**:
    - If `current layer` is of length 1: **success**.
    - For all adjacent pairs in `current layer`, generate all possible block choices above, as per the allowed map.
    - For the next row, try all combinations (cross product of choices for each position), and proceed recursively.

#### **Memoization:**
To prune repeated work (since bottom can be up to 6, and only 6 different block types), **memoize**: for a given current string/layer, does it lead to the top? (`unordered_map<string, bool> memo`).

#### **Complexity:**
- The input is small enough (`len <= 6`) to allow this exhaustive search with memoization to be optimal.

---

## 4. **Clean C++ Solution**

```cpp
#include <unordered_map>
#include <vector>
#include <string>
using namespace std;

class Solution {
public:
    // Map "AB" -> {C1, C2, ...}
    unordered_map<string, vector<char>> allowed_map;
    unordered_map<string, bool> memo;

    bool dfs(const string& row) {
        if (row.length() == 1) return true;
        if (memo.count(row)) return memo[row];

        // For all positions in this row, make a list of possible candidates above
        vector<vector<char>> choices;
        for (int i = 0; i + 1 < row.length(); ++i) {
            string base = row.substr(i, 2);
            if (!allowed_map.count(base)) {
                return memo[row] = false;
            }
            choices.push_back(allowed_map[base]);
        }

        // Now try every combination for possible next rows (using recursion)
        string next_row(choices.size(), ' ');

        function<bool(int)> build_next = [&](int pos) {
            if (pos == choices.size()) {
                return dfs(next_row); // reached one candidate for next row
            }
            for (char c : choices[pos]) {
                next_row[pos] = c;
                if (build_next(pos + 1)) return true;
            }
            return false;
        };

        return memo[row] = build_next(0);
    }

    bool pyramidTransition(string bottom, vector<string>& allowed) {
        // Build the allowed_map
        for (const string& s : allowed) {
            string key = s.substr(0, 2);
            allowed_map[key].push_back(s[2]);
        }
        memo.clear();
        return dfs(bottom);
    }
};
```

---

## 5. **Example Explained**

Let's explain Example 1:

```
bottom = "BCD"
allowed = ["BCC","CDE","CEA","FFF"]
```

- **allowed_map will be:**
   - "BC" → ['C']
   - "CD" → ['E']
   - "CE" → ['A']
   - "FF" → ['F']

- Start with "BCD".
    - "BC" → can stack 'C' above
    - "CD" → can stack 'E' above
- So, next possible row is "CE".
- "CE":
    - "CE" → can stack 'A' above
- So, next row is "A" (top).
- SUCCESS! (Every triangle used is in allowed).

**So the answer is `true`.**

|--------------------------|----------------|---------------------|-------------------------------|
| DFS + Memoization        | O(6^N * N)     | N=6 is feasible     | Memoize layer, prune deadends |
| BFS                      | O(6^N)         | Also possible, but more memory use  | Use queue, process each layer |
