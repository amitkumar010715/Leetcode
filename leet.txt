Let's tackle the problem step by step!

---

## 1. **Summary**

You are given an undirected graph on `n` nodes (labelled `0` to `n-1`) with edges specified as pairs. Your task is to count how many **complete connected components** it has. A component is **complete** if every pair of nodes in it is directly connected by an edge (a clique).

---

## 2. **Constraints & Edge Cases**

- **Constraints:**
  - `1 <= n <= 50` (small, so `O(n^2)` algorithms are fine!)
  - Edges are unique, undirected, and nodes are not self-connected.

- **Edge cases:**
  - No edges (`edges = []`): Each node is its own component, each is trivially complete (single node = clique).
  - All nodes connected into a single complete graph (clique).
  - Several disconnected components, possibly of varying sizes, some complete, some not.

---

## 3. **Optimal Algorithm**

Given `n` is small, we can:
- **Step 1:** Build adjacency lists for the graph.
- **Step 2:** Use BFS/DFS to find all connected components.
- **Step 3:** For each component, check if it's complete:
    - For a component with `k` nodes, there must be exactly `k*(k-1)/2` edges among them.
    - Count the number of edges within the component (avoid double counting).
    - If yes, increment the answer.

### **Why does this work?**
- In a complete graph, each node is connected to every other node.
- For a component of size `k`, maximum edges = C(k, 2) = k*(k-1)/2.

---

## 4. **C++ Solution**

```cpp
#include <vector>
#include <queue>

using namespace std;

class Solution {
public:
    int countCompleteComponents(int n, vector<vector<int>>& edges) {
        // Build the adjacency list.
        vector<vector<int>> g(n);
        for (const auto& e : edges) {
            g[e[0]].push_back(e[1]);
            g[e[1]].push_back(e[0]);
        }
        
        vector<bool> vis(n, false);
        int ans = 0;
        
        for (int i = 0; i < n; ++i) {
            if (!vis[i]) {
                // BFS to collect all nodes (vertices) in this component
                vector<int> comp;
                queue<int> q;
                q.push(i);
                vis[i] = true;
                while (!q.empty()) {
                    int u = q.front(); q.pop();
                    comp.push_back(u);
                    for (int v : g[u]) {
                        if (!vis[v]) {
                            vis[v] = true;
                            q.push(v);
                        }
                    }
                }
                // Now, check if 'comp' is a complete component
                int sz = comp.size();
                int edgeCnt = 0;
                for (int u : comp) {
                    for (int v : g[u]) {
                        // Only count edges to other nodes in this component
                        if (u < v && find(comp.begin(), comp.end(), v) != comp.end()) {
                            edgeCnt++;
                        }
                    }
                }
                // A complete component of size sz has sz*(sz-1)/2 edges
                if (edgeCnt == sz * (sz - 1) / 2) {
                    ans++;
                }
            }
        }
        return ans;
    }
};
```

## 5. **Example Explanation**

#### Example 1
**Input:**  
`n = 6, edges = [[0,1],[0,2],[1,2],[3,4]]`

Component breakdown:
- Component 1: `{0,1,2}` &rarr; edges: 0-1, 0-2, 1-2 ⇒ all pairs connected ⇒ complete.
- Component 2: `{3,4}` &rarr; edge: 3-4 ⇒ complete.
- Component 3: `{5}` (no edges) ⇒ single node ⇒ complete.

**Total complete components:** 3

## 6. **Comments on Efficiency**

- Max `n=50` allows us to do BFS/DFS, and even up to `O(n^3)` is OK for such small inputs.
- For edge counting in each component, an alternative for faster approach: use a `set` for O(1) lookup (but in practice, current code is fast given constraints).
