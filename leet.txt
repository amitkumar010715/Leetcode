Let's go step by step:

---

## 1. **Short Summary**

Given a binary string `s` and an integer `k`, find the **shortest** substring of `s` that contains exactly `k` ones (`1`). Among all such substrings of minimum length, return the **lexicographically smallest** one. If none exists, return an empty string.

---

## 2. **Constraints & Edge Cases**

- `1 <= s.length <= 100` (string is short! O(N^2) is acceptable)
- `1 <= k <= s.length`
- May be 0 or more substrings with exactly `k` ones.
- If `s` has fewer than `k` ones, return `""` (impossible).
- If `k == 0`, not possible under constraints.
- Substrings may overlap.
- All characters are '0' or '1'.

**Edge Cases:**
- String of all `0`.
- String of all `1`.
- `k > total # of ones in s`.

---

## 3. **Optimal Algorithm**

Because the string is small (`<=100`), we can brute force all substrings, but with optimization:

**Steps:**
1. Use a sliding window to find all substrings with exactly `k` ones.
2. For each such substring, record its length and string.
3. Find the **minimum** length over all such substrings.
4. Among substrings of that minimal length, select the **lex smallest** one.

**How to efficiently scan for substrings with exactly `k` ones?**

- Use two pointers (`left`, `right`) to maintain a window, and a variable `cnt` for the number of ones in `[left, right]`.
- Move the right pointer and expand the window.
- While `cnt > k`, move left pointer right (shrinking).
- When `cnt == k`, consider substring `[left, right]` as a candidate.

---

### Time Complexity

- Each character is expanded and contracted at most once: O(N) + O(N) = O(N)
- For each valid substring, storing and comparing: O(1) for up to O(N^2) substrings.
- Given N <= 100, this is acceptable.

---

## 4. **Clean C++ Solution**

```cpp
#include <string>
using namespace std;

class Solution {
public:
    string shortestBeautifulSubstring(string s, int k) {
        int n = s.size();
        int left = 0, ones = 0;
        int minLen = n+1;
        string answer = "";

        for (int right = 0; right < n; ++right) {
            if (s[right] == '1') ones++;

            // shrink left pointer if we have more than k ones
            while (ones > k && left <= right) {
                if (s[left] == '1') ones--;
                left++;
            }

            // when exactly k ones, consider the window [left, right]
            if (ones == k) {
                int currentLen = right - left + 1;
                string curr = s.substr(left, currentLen);
                if (currentLen < minLen || (currentLen == minLen && curr < answer)) {
                    minLen = currentLen;
                    answer = curr;
                }
            }
        }
        return answer;
    }
};
```

---

## 5. **Example Explanation**

**Example 1: `s = "100011001"`, `k = 3`**

We look for substrings with exactly 3 ones.

Let's do the sliding windows:
- Indices 0-5: `"100011"` – ones=3, len=6
- Indices 1-6: `"000110"` – ones=2 (skip)
- Indices 2-7: `"001100"` – ones=2 (skip)
- Indices 3-8: `"011001"` – ones=3, len=6
- ... etc.

But optimal is:
- For window starting at 4: ones=3 at window [4,8] (`"11001"`) – len=5.
- Any substring shorter? Let's check:
    - `"11001"` is 5 chars, and any substring shorter will lack enough ones.
- Among all minimal substrings of length 5, `"11001"` is the lex smallest.

## **Final Output:**  
`"11001"`

---

> **In summary**:  
Use sliding window, find all minimal length substrings with exactly `k` ones, return the lex smallest one (or empty string if none).  
Code above does this efficiently for the given constraints.
