## 1. Short Summary

This is a **two-player game** played on an array of piles of stones (even number of piles, positive integers). Players alternately pick either the first or last pile each turn. Alice goes first. The total number of stones is **odd** (so no ties possible). Both play optimally. **Return `true` if Alice can guarantee a win.**

## 3. Optimal Algorithm & Explanation

### Insight

This is a classic **game theory / DP** problem. Both players pick from either end, wanting to maximize their own score.

#### Main Observations

- There is an **even number of piles**.
- The rules ensure that the game **cannot be tied**.
- **Alice always wins** if both play optimally!
    - At each turn, Alice can always ensure victory thanks to the **even length** of the array. She can pick either the even-indexed or odd-indexed piles entirely by her choices (parity argument, see below).

#### Why does Alice always win?

Since number of piles is even, she can decide at the start to stick to all even or all odd indexed piles, whichever sum is greater. On her first pick, she chooses the end which aligns with the set (even or odd indices) with the larger sum. After that, she can always maintain her picks alternating with Bob and force the parity of indices.

Given `sum(piles) % 2 == 1`, there are no ties, and Alice can always collect the higher-sum half because she moves first and both halves have the same length.

#### Therefore

- **Always return `true`!**
- Dynamic Programming solution exists, but not needed: both optimal and required only for variant questions.

#### For completeness, here is the DP approach (for variants):

Let `dp[i][j]` represent the maximum score player can achieve from subarray `piles[i..j]` minus the opponent's score from that subarray.  
- when `i == j`, `dp[i][i] = piles[i]`
- when `i < j`, 
    ```
    dp[i][j] = max(
        piles[i] - dp[i+1][j], // Pick left, opponent left with dp[i+1][j]
        piles[j] - dp[i][j-1]  // Pick right, opponent left with dp[i][j-1]
    )
    ```
If `dp[0][n-1] > 0`, Alice wins.

But for this problem, just return true.

### Solution 2: Full DP (For completeness)

```cpp
class Solution {
public:
    bool stoneGame(vector<int>& piles) {
        int n = piles.size();
        vector<vector<int>> dp(n, vector<int>(n, 0));
        // Base case: one pile
        for(int i = 0; i < n; ++i) {
            dp[i][i] = piles[i];
        }
        // Fill for longer intervals
        for(int len = 2; len <= n; ++len) {
            for(int i = 0; i + len -1 < n; ++i) {
                int j = i + len - 1;
                dp[i][j] = max(
                    piles[i] - dp[i+1][j],
                    piles[j] - dp[i][j-1]
                );
            }
        }
        // If Alice's net score > 0, she wins
        return dp[0][n-1] > 0;
    }
};
```

## 5. Example Explanation

### Example: `piles = [5, 3, 4, 5]`

Let's see:

- Alice: pick 1st `5` (row becomes `[3,4,5]`)
    - Bob: pick `3`; Alice: pick `5` (gets `5+5=10`)
    - Bob: pick `5`; Alice: pick `4` (gets `5+4=9`)
- Or Alice: pick last `5` (row becomes `[5, 3, 4]`)
    - Bob: pick `5`, Alice: pick `4` (Alice gets `5+4=9`)
    - Bob: pick `3`, Alice: pick `5` (Alice gets `5+5=10`)

In all best lines, Alice always gets more, because she can control the parity of her picks. So Alice wins, return `true`.
