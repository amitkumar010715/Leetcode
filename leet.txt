Let's break down the solution:

---

## 1. **Short Summary**

Given an undirected graph of `n` cities (numbered 1..n) and bidirectional roads (with weights), return the **minimum possible score** (the *minimum edge weight* along any path) between city 1 and city n. A path may revisit cities or roads. The solution is to find the minimum edge in the **connected component** containing both 1 and n (since you can always traverse any edge multiple times if needed).

---

## 2. **Constraints & Edge Cases**

- Up to `10^5` nodes, `10^5` edges: *linear or near-linear solution required*.
- There may be loops or repeated cities/roads on a path.
- There is *guaranteed* to be a path from 1 to n.
- Our goal: Among all paths from 1 to n, **maximize the "bottleneck"**, i.e., the *minimum* edge on the path.

### Key Observations

- **Any edge in the component containing 1 can be used as part of some path from 1 to n.**
- **The answer is simply the minimum weight of any edge in the connected component containing node 1.** (Since cycles/loops are allowed, you can always detour to use any edge you like within the connected component!)

---

## 3. **Optimal Algorithm**

### Steps

1. **Build the graph as adjacency list**.
2. **BFS/DFS from node 1** to find all nodes in its connected component and *collect all edge weights in this component*, keeping track of the minimum weight found.
3. Since 1 and n are guaranteed connected, and the answer is the minimum edge in this component — output the recorded minimum.

- **Complexity:** O(n + m) where m = number of roads.

---

## 4. **Clean C++ Solution**

```cpp
#include <vector>
#include <queue>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minScore(int n, vector<vector<int>>& roads) {
        vector<vector<pair<int, int>>> adj(n + 1);   // (neighbor, edge weight)
        for (const auto& r : roads) {
            adj[r[0]].emplace_back(r[1], r[2]);
            adj[r[1]].emplace_back(r[0], r[2]);
        }
        
        vector<bool> visited(n + 1, false);
        queue<int> q;
        q.push(1);
        visited[1] = true;
        int minEdge = INT_MAX;
        
        while (!q.empty()) {
            int u = q.front(); q.pop();
            for (auto& [v, w] : adj[u]) {
                minEdge = min(minEdge, w);
                if (!visited[v]) {
                    visited[v] = true;
                    q.push(v);
                }
            }
        }
        return minEdge;
    }
};
```

---

## 5. **Example Explained**

**Example 1:**

```
n = 4, roads = [[1,2,9], [2,3,6], [2,4,5], [1,4,7]]
```
- Graph:
  - 1-2 (9)
  - 2-3 (6)
  - 2-4 (5)
  - 1-4 (7)

**All cities (1..4) are connected.**

Traversing edges from node 1 (via BFS/DFS), we encounter these edge weights: 9 (1-2), 6 (2-3), 5 (2-4), 7 (1-4).

- **Minimum edge = 5 (2-4).**
- Any path from 1 to 4 can take (1-2-4); path's minimum edge = min(9,5) = 5.
- *But regardless of path, you can't get a path with less than 5 as the "bottleneck".*

**Return:** `5`.

---

## **Conclusion**

- The solution simply computes the minimum edge weight in the connected component containing node 1.
- Works in linear (O(n + m)) time and space.
