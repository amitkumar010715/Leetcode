Let's break down the solution step-by-step:

---

## **1. Summary**

Given points on the **boundary of a square**, select **k** points such that the **minimum** Manhattan distance between any pair is **maximized**. Return this maximum possible minimum Manhattan distance.

---

## **2. Constraints & Edge Cases**

- **side:** up to 1e9 (but positions in input are always among the given set)
- **points.length:** up to 15,000 (all points on boundary, unique)
- **k:** up to 25 (small)
- **All points are unique and on the boundary.**
- Why is this hard? Looking for a subset maximizing the min pairwise Manhattan distance, with up to 15k points (can't brute-force all k-subsets).

**Edge Cases:**
- All 4 corners: only 4 points, must pick all.
- Many points "clustered" on the same side.

---

## **3. Optimal Algorithm**

### **Observation**
- **Manhattan distance** on square boundary is _never larger than side * 2_.
- Given unique, up to 15k boundary points—**k is very small**.

### **Approach: Binary Search + Greedy Check**
- **Key Trick:** The problem reduces to: *For a candidate answer `D`, is it possible to pick `k` points among the given points so that every pair has Manhattan distance at least `D`?*
- This is a classic "**maximum minimum distance**" problem, solved with binary search.

**Steps:**

1. **Binary Search** on answer (distance D): D in [0, 2*side].
2. For each candidate D, **Greedy Check**: Can we select k points from the list such that pairwise minimal Manhattan distance is at least D?

**Implementation of Check Function:**
- Since k is small (<=25), can use **greedy selection**:
    - Sort points in any order (or try all as possible starting points, for more accuracy).
    - For each new point, only add it to our current set if it has Manhattan distance at least D to all previously selected points.
    - If you manage to select k points, then D is feasible.

- **Optimization:** Pre-sort points for consistent behavior; though starting from any point is usually sufficient because of small k.

**Time Complexity:**
- Binary Search: O(log(maxD)) ~ 31
- For each check: O(points.length * k * k)
- Acceptable for points.length = 15k, k = 25, log(2e9)=31.

## **4. C++ Solution**

```cpp
#include <vector>
#include <algorithm>
#include <cmath>
using namespace std;

class Solution {
public:
    int maxManhattanDistance(int side, vector<vector<int>>& points, int k) {
        int n = points.size();

        // Check if for given distance d, we can pick at least k points
        auto check = [&](int d) -> bool {
            // Try every point as potential starting point? Not necessary, just one suffices for small k
            // (but can be enhanced if needed)
            // Let's try greedy select
            vector<int> used;
            for (int s = 0; s < n; ++s) {
                vector<int> sel = {s};
                for (int i = 0; i < n && sel.size() < k; ++i) {
                    if (i == s) continue;
                    bool ok = true;
                    for (int idx : sel) {
                        int dist = abs(points[i][0] - points[idx][0]) + abs(points[i][1] - points[idx][1]);
                        if (dist < d) { ok = false; break; }
                    }
                    if (ok) sel.push_back(i);
                }
                if (sel.size() >= k)
                    return true;
            }
            return false;
        };

        int lo = 0, hi = 2*side+1; // search for maximum possible min distance
        while (lo < hi) {
            int mid = lo + (hi-lo)/2;
            if (check(mid)) {
                lo = mid+1;
            } else {
                hi = mid;
            }
        }
        return lo-1;
    }
};
```

## **5. Example Explanation**

### Example 1:
**Input:**  
`side = 2`, `points = [[0,2],[2,0],[2,2],[0,0]]`, `k = 4`

All 4 points are square corners.  
**Max Manhattan distance** between any pair is either 2 (side) or 4 (across diagonal).

- Pick all 4 points. The smallest pairwise Manhattan distance is exactly 2.
- Can't do better, because if you exclude any point, the minimum distance increases, but you must pick all four.

**Output:** `2`
