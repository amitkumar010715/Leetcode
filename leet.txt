---

## 1. **Short Summary**

You need to build a dynamic array with API calls:
- `append(val)`: add a value to the end,
- `addAll(inc)`: add an increment to **every element**,
- `multAll(m)`: multiply **every element**,
- `getIndex(idx)`: return value at index modulo \(10^9+7\), or -1 if out of bounds.

The challenge is to ensure **all operations (especially getIndex) are efficient**, as the naive approach would be too slow for many operations.

---

## 2. **Constraints & Edge Cases**

- Values and operations (`val`, `inc`, `m`) are small (1 to 100).
- Sequence length (`idx`) can be up to \(10^5\).
- You may have up to \(10^5\) calls in total.
- Edge Cases:
  - Out-of-bound index queries.
  - Append values when additive/multiplicative operations have already occurred.
  - Chains of `addAll` and `multAll` operations must be combined efficiently.

---

## 3. **Optimal Algorithm**

### **Key Observations**

- *Naive manipulation* (updating every value) on each operation leads to O(N) time per operation. This is **too slow**.
- Each value can be represented with some **stored value and the global "multiplicative" and "additive" state** at the time of append.

### **Efficient Representation**

At each step, maintain:
- `mul` = overall multiplication factor applied since creation.
- `add` = overall addition applied since creation.

For each element, when you `append(val)`, capture:
- `applied_mul` and `applied_add` at that time.

**When querying at index i:**
- Let
  - `val_i` = value appended at i,
  - `mul_i`, `add_i` = the values of `mul` and `add` at the moment `val_i` was appended,
  - `cur_mul`, `cur_add` = current `mul`, `add`.

The value at position i is:
```
value = val_i * (cur_mul / mul_i) + (cur_add - add_i * (cur_mul / mul_i))
```

All math must be mod \(10^9+7\).

#### **How does this work?**
- After you append, you can factor all later `multAll` and `addAll` as:
    - `val' = val* all_mult + all_adds`
- For each element, just store the multipliers/adders up to that append, then "catch up" to now on query using modular arithmetic (and modular inverses for divide).

#### **Why division?**
- Because `multAll` is applied multiplicatively, so to "undo" the effect up to the append time, you multiply by the modular inverse.

#### **Time complexity:**
- `O(1)` for all operations, using modular inverses for division.

---

## 4. **C++ Solution**

```cpp
class Fancy {
    using ll = long long;
    const int MOD = 1e9 + 7;
    vector<ll> values, appendMul, appendAdd;
    ll mul = 1, add = 0;

    // Helper to compute modular inverse under MOD
    ll modinv(ll a) {
        ll res = 1, p = MOD - 2;
        while (p) {
            if (p & 1) res = res * a % MOD;
            a = a * a % MOD;
            p >>= 1;
        }
        return res;
    }
public:
    Fancy() {
        values.clear();
        appendMul.clear();
        appendAdd.clear();
        mul = 1;
        add = 0;
    }
    
    void append(int val) {
        values.push_back(val);
        appendMul.push_back(mul);
        appendAdd.push_back(add);
    }
    
    void addAll(int inc) {
        add = (add + inc) % MOD;
    }
    
    void multAll(int m) {
        mul = mul * m % MOD;
        add = add * m % MOD;
    }
    
    int getIndex(int idx) {
        if (idx >= values.size()) return -1;
        ll val = values[idx];
        ll mulAtInsert = appendMul[idx], addAtInsert = appendAdd[idx];
        // Now, update val to current state:
        // x' = val * (cur_mul / insert_mul) + (cur_add - insert_add * (cur_mul / insert_mul))
        ll inv = modinv(mulAtInsert);
        ll m = mul * inv % MOD;
        ll a = (add - addAtInsert * m % MOD + MOD) % MOD;
        ll res = (val * m % MOD + a) % MOD;
        return (int)res;
    }
};
```

---

## 5. **Example Explanation**

Let's follow this sequence:
```
fancy.append(2);   // fancy sequence: [2]
fancy.addAll(3);   // [5]
fancy.append(7);   // [5, 7]
fancy.multAll(2);  // [10, 14]
fancy.getIndex(0); // return 10

fancy.addAll(3);   // [13, 17]
fancy.append(10);  // [13, 17, 10]
fancy.multAll(2);  // [26, 34, 20]
fancy.getIndex(0); // return 26
fancy.getIndex(1); // return 34
fancy.getIndex(2); // return 20
```

**Let's work through getIndex(2):**
- When appending 10, state is: mul=2, add=3
  - store val=10, mul=2, add=3
- After `multAll(2)`, global mul=4, add=6

- For index 2:
    - cur_mul=4, cur_add=6, insert_mul=2, insert_add=3,
    - m = cur_mul / insert_mul = 4 * inv(2) mod MOD = 2
    - a = cur_add - insert_add*m = 6 - 3*2 = 0
    - value = val * m + a = 10*2 + 0 = 20

---

**Summary**
- Track the global multiplication/addition values;
- For each append, store their values at insert time;
- Use modular inverse to calculate the effect of operations since append.

---

**This C++ solution is fully optimal, O(1) per operation, as required.**
