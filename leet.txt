---

## 1. Short Summary

**Problem:**  
Given two `n x n` binary matrices (`img1`, `img2`), you can "slide" one grid over the other (only in up, down, left, right - no rotation), and your goal is to maximize the overlap, i.e., maximize the number of positions where both images have `1` after translation.

---

## 2. Constraints & Edge Cases

### **Constraints**
- `1 <= n <= 30`
- Both matrices are `n x n` square.
- Matrix elements are either `0` or `1`.

### **Edge Cases**
- Both matrices are all zeros (overlap is 0).
- Both matrices are all ones (maximum overlap is n * n).
- Only one '1' in each, potentially at different coordinates (overlap is at most 1 after alignment).
- Sparse matrices (more zeros), so translating might only match a few positions.
- The solution must handle every possible translation (from complete left/up to complete right/down within bounds).

---

## 3. Optimal Algorithm

### **Naive Brute Force**

For each possible translation (shift right/left and up/down), shift `img1` over `img2` and count the overlap. Given both matrices are at most 30x30, the total number of possible translations is `(2n-1)` for rows and `(2n-1)` for columns, making at most `O(n^4)` operations for a naïve implementation—acceptable as `30^4 = 810,000`.

### **Optimized Idea**

Instead of checking every translation with nested loops, we can:
- Precompute coordinates of all 1's in both matrices.
- For each pair of 1's (`(i1, j1)` from `img1` and `(i2, j2)` from `img2`), compute translation vector `(dx, dy) = (i2 - i1, j2 - j1)`.
- For each such vector, count how many align in that way (using a hash map).
- The answer is the maximum count among all translation vectors.

This reduces time complexity to **O(K^2)** where K is the number of 1's (which never exceeds 900), so it's very efficient.

#### **Steps**
1. Record coordinates of 1's in both images as two arrays (`ones1`, `ones2`).
2. For every pair, compute difference `(dx, dy)`.
3. Count frequencies of all such diffs using a map.
4. The maximum frequency is the solution.

---

## 4. Clean C++ Solution

```cpp
#include <vector>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int largestOverlap(vector<vector<int>>& img1, vector<vector<int>>& img2) {
        int n = img1.size();
        vector<pair<int, int>> ones1, ones2;

        // Collect coordinates of 1s in both images
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < n; ++j) {
                if (img1[i][j] == 1) ones1.push_back({i, j});
                if (img2[i][j] == 1) ones2.push_back({i, j});
            }
        }

        unordered_map<long long, int> counter;
        int maxOverlap = 0;

        // For each pair of 1's, count the translation vector
        for (auto &p1 : ones1) {
            for (auto &p2 : ones2) {
                // Offset so that negative shifts become positive as map key
                int dx = p2.first - p1.first;
                int dy = p2.second - p1.second;
                // Encode (dx, dy) into a single long long
                long long key = ((long long)dx << 32) | ((unsigned int)dy);
                counter[key]++;
                maxOverlap = max(maxOverlap, counter[key]);
            }
        }

        return maxOverlap;
    }
};
```

## 5. Example Explanation

### Example 1

```
img1 = [[1,1,0],
        [0,1,0],
        [0,1,0]]

img2 = [[0,0,0],
        [0,1,1],
        [0,0,1]]
```

**Step by Step:**
- The largest overlap happens when you shift `img1` right by 1 and down by 1:
    - All 1's in `img1` that land on a 1 in `img2`:
        - At position `(1,1)` in both (center)
        - At position `(2,1)` in `img1` lands at `(3,2)`, which is out of bounds, so overlap is only possible for points within the bounds.
        - At position `(0,1)` in `img1` lands at `(1,2)` in `img2`, which is 1.
        - At position `(0,0)` in `img1` lands at `(1,1)` in `img2`, which is 1.
    - Total overlap = **3**.
