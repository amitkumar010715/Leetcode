## 1. **Summary**

This problem asks us to find the minimum element in a rotated sorted array that **may contain duplicates**. The array was initially sorted in ascending order and then rotated between 1 and n times. We need to do this as efficiently as possible.

---

## 2. **Constraints & Edge Cases**

- **Constraints:**
    - Length of array, n: `1 <= n <= 5000`
    - Array elements: `-5000 <= nums[i] <= 5000`
    - Array contains **at least one element**.
    - The array can contain **duplicate values**.
    - The array is rotated between 1 and n times, so it’s always rotated at least once.

- **Edge Cases:**
    - All elements are the same (e.g., `[2,2,2,2,2]`)
    - The minimum is at the far end, after rotation (e.g., `[2,2,2,1,2]`)
    - The array is not rotated (e.g., `[1,2,3,4,5]`)
    - The array is rotated so the minimum is at the very end or start

---

## 3. **Optimal Algorithm & Reasoning**

The classic binary search for "Find Minimum in Rotated Sorted Array" doesn't handle **duplicates** well. With duplicates, in certain cases, you can't easily decide which half to discard.

### Key observations:
- Use two pointers: `left` and `right`.
- Middle point: `mid = left + (right - left) / 2`
- If `nums[mid] < nums[right]`: The minimum is in the **left** part (including `mid`).
- If `nums[mid] > nums[right]`: The minimum is in the **right** part (excluding `mid`).
- If `nums[mid] == nums[right]`: Can't judge which side, **reduce search space** by `right--`.

### Time Complexity:
- In the worst-case (e.g. all elements the same), it's **O(n)**
- In the average case (little/no duplicates), it’s **O(log n)**

---

## 4. **Clean C++ Solution**

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int left = 0, right = nums.size() - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] < nums[right]) {
                right = mid; // Min is at or before mid
            } else if (nums[mid] > nums[right]) {
                left = mid + 1; // Min is after mid
            } else {
                // nums[mid] == nums[right], cannot decide, shrink bounds
                right--;
            }
        }
        return nums[left];
    }
};
```

---

## 5. **Example Explanation**

**Example:** `nums = [2,2,2,0,1]`

- Initial: `left = 0`, `right = 4` (`nums[left]=2`, `nums[right]=1`)
- 1st Iteration:
    - `mid = 2`, `nums[mid]=2`
    - `nums[mid] > nums[right]` (2 > 1); min is after mid.
    - Move `left` to `mid + 1`: `left = 3`
- 2nd Iteration:
    - `left = 3`, `right = 4`
    - `mid = 3`, `nums[mid]=0`
    - `nums[mid] < nums[right]` (0 < 1); min is at or before mid.
    - Move `right` to `mid`: `right = 3`
- Loop ends (`left == right`): return `nums[3] = 0`
