## 1. **Short Summary**

Given an array `nums` and an integer `k`, find the minimum number of removals needed so that the remaining (non-empty) array is "balanced": `max <= min * k`. You may remove any elements. Return that minimum number.

---

## 2. **Constraints & Edge Cases**

- **Constraints:**
  - `1 <= nums.length <= 10^5`
  - `1 <= nums[i] <= 10^9`
  - `1 <= k <= 10^5`
- **Edge Cases:**
  - Already balanced: answer is 0.
  - Only one element: always balanced, answer is 0.
  - All elements the same: always balanced.
  - Large input size: need *O(n log n)* or better.
  - Any subset of size ≥ 1 is valid—as long as `max <= min * k`.

---

## 3. **Optimal Algorithm**

### **Observations**

- **Balanced Segment:** After removing any elements, the remaining array (not necessarily contiguous) should satisfy `max <= min * k`.
- **Order-independent:** Since removing elements is allowed anywhere, we only care about the possible values of `min` and `max` in our subset.
- **Optimal:** To **minimize removals**, we want the **largest possible balanced subset**.
- **Sorting:** This suggests sorting the array and finding **the largest window** where `nums[j] <= nums[i] * k`.

### **Approach: Sliding Window (Two Pointers)**

1. **Sort** the array.
2. Use two pointers `i` (left) and `j` (right) to find the largest window `[i, j]` where `nums[j] <= nums[i] * k`.
    - For each `i`, move `j` as far right as possible.
    - The size of the window is `j - i + 1`.
3. The answer is: `n - max_window_size` (because the rest are removals).

- **Time complexity:** O(n log n) (due to sorting), O(n) for sliding window.

---

## 4. **C++ Solution**

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minimumRemovals(vector<int>& nums, int k) {
        int n = nums.size();
        sort(nums.begin(), nums.end());

        int maxWindow = 1;
        int j = 0;
        for (int i = 0; i < n; ++i) {
            // Expand j as long as balanced
            while (j < n && (long long)nums[j] <= (long long)nums[i] * k) {
                ++j;
            }
            // Now nums[j] > nums[i] * k or j==n
            // Valid window: [i, j-1]
            maxWindow = max(maxWindow, j - i);
        }
        return n - maxWindow;
    }
};
```

## 5. **Example Explained**

**Example:** `nums = [2, 1, 5], k = 2`

- Sort: `[1, 2, 5]`
- For each starting point:
  - `i = 0` (nums[0]=1): Find the farthest `j` with `nums[j] <= 1*2=2`:
    - j=0: 1 <= 2 ✔️
    - j=1: 2 <= 2 ✔️
    - j=2: 5 <= 2 ✖️
    - So max window: [0,1] → size 2
  - `i = 1` (nums[1]=2): `j` starts at 1.
    - j=1: 2 <= 4 ✔️
    - j=2: 5 <= 4 ✖️ → window [1,1], size 1
  - `i = 2` (nums[2]=5): `j` starts at 2.
    - j=2: 5 <= 10 ✔️ → window [2,2], size 1

**Max window size is 2**, so answer is `3-2=1` (*remove 5*).

---

### **Summary Table**

| i(start) | j(end) | Balanced Subarray | Size |
|----------|--------|-------------------|------|
|    0     |   1    | [1, 2]            |  2   |
|    1     |   1    | [2]               |  1   |
|    2     |   2    | [5]               |  1   |

Final **answer: 1** (remove 5 → [1,2] is balanced).
