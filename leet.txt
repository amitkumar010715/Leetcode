Let's go through each of your requirements:

---

## 1. **Short Summary**

Given an array of stones, in each round you split them into two non-empty parts. Bob throws away the part with the **larger sum** (or if equal, you choose), and your score increases by the sum of the remaining part. The process repeats with the remaining stones until only one is left. Return the maximum possible score you can acquire.

---

## 2. **Constraints & Edge Cases**

- **Constraints:**
  - 1 ≤ stoneValue.length ≤ 500
  - 1 ≤ stoneValue[i] ≤ 1,000,000

- **Edge Cases:**
  - If only one stone, your score is 0 (no possible splits).
  - If all values are the same, there are often multiple valid splits with equal sums.
  - You must consider optimal splits at every step, as greedy doesn't work.

---

## 3. **Optimal Algorithm**

This is a classic DP problem over intervals.

- **Key observations:**
  - For every subarray `[i, j]`, we store the max score that Alice can obtain, i.e., `dp[i][j]`.
  - For every possible division between `i` and `j`, we check the sum of the left and right halves.
  - If the sum of the left half ≤ right, Bob removes the right half and Alice gets `sum(left)` plus the best from the left half: `sum(left) + dp[i][k]`.
  - If the right sum < left, Alice gets `sum(right)` plus best from the right: `sum(right) + dp[k+1][j]`.
  - If both are equal, Alice can choose the better of the two options.

**Steps:**

1. Build a prefix sum array for O(1) range sums.
2. Use DP: `dp[i][j] = max score Alice can get from subarray [i, j]`.
3. For every split point, consider the described options and maximize the result.
4. Final answer is `dp[0][n-1]`.

- Time Complexity: O(N³) (naive), but with optimized transitions, can be brought down to O(N²).

---

## 4. **Clean C++ Solution**

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int stoneGameV(vector<int>& stoneValue) {
        int n = stoneValue.size();
        vector<int> prefix(n + 1, 0);
        for (int i = 0; i < n; ++i)
            prefix[i + 1] = prefix[i] + stoneValue[i];
        
        // dp[i][j]: max score for subarray [i, j]
        vector<vector<int>> dp(n, vector<int>(n, 0));
        
        for (int len = 2; len <= n; ++len) { // length of subarray
            for (int i = 0; i + len <= n; ++i) { // start index
                int j = i + len - 1; // end index
                // Try all possible first splits
                for (int k = i; k < j; ++k) {
                    int left_sum = prefix[k + 1] - prefix[i];
                    int right_sum = prefix[j + 1] - prefix[k + 1];
                    if (left_sum < right_sum)
                        dp[i][j] = max(dp[i][j], left_sum + dp[i][k]);
                    else if (left_sum > right_sum)
                        dp[i][j] = max(dp[i][j], right_sum + dp[k + 1][j]);
                    else // equal
                        dp[i][j] = max(dp[i][j], left_sum + max(dp[i][k], dp[k + 1][j]));
                }
            }
        }
        return dp[0][n - 1];
    }
};
```

## 5. **Example Explanation**

**Example 1:**  
Input: `[6, 2, 3, 4, 5, 5]`  
Output: `18`

**Let's see how we can get 18:**

- Split `[6,2,3|4,5,5]` (sums: 11, 14) → Bob throws away right half, Alice gets `11`.
- Now Alice has `[6,2,3]`:
  - Split `[6|2,3]` (sums: 6, 5) → Bob removes left, Alice gets `5` (total now 16).
- Now Alice has `[2,3]`:
  - Split `[2|3]` → Bob removes right, Alice gets `2` (total now 18).
- Finally, only one stone left. Done.

This is just one optimal sequence; the DP ensures the maximum is considered at each split.
