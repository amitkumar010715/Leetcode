Let's break down the problem as requested:

---

## 1. **Short Summary**

Given a permutation of numbers from 0 to n-1, you can **only** rotate the array left by one or reverse the entire array. You must return the *minimum number of such moves* to sort the array in increasing order. If not possible, return -1.

---

## 2. **Constraints & Edge Cases**

- **n** ≤ 100,000; solution must be O(n) or O(n log n).
- Only two moves: *rotate left by one* and *reverse entire array*.
- The array is always a permutation; all numbers from 0 to n-1 are present.
- Not all permutations are reachable (not all can be sorted with these moves).
- Important edge cases:
   - The array is **already sorted** (`[0,1,...,n-1]`) → Output: 0.
   - The array is **reverse sorted** (`[n-1, n-2, ..., 0]`) → Output: 1.
   - The sorted array can be obtained by only **rotations** or only **(rotate(s) + reverse)**.
   - Arrays with "wrecked" order (can't be rotated/reversed-rotated to sort) → Output: -1.

---

## 3. **Optimal Algorithm & Intuition**

### **Key Insights**
- **Rotate left by k**: `[A, B, ..., Z]` → `[B, ..., Z, A]`. If you rotate X times, the relative order does not change; only the starting position does.
- **Reverse**: Flips the array.

**The only sequences you can generate:**
- Any *rotation* of the original ("forward rotated" forms).
- Any *rotation of the reversed array* ("reverse rotated" forms).

#### To reach the sorted array `[0,1,...,n-1]`, `nums` must be:
- **Either** a rotation of `[0,1,...,n-1]`,
- **Or** a reversed and rotated version, i.e., a rotation of `[n-1, ..., 0]`.

#### **Approach**
- For **rotations**:
   - For each possible rotation k, if `nums` matches `[k, k+1, ..., n-1, 0,..., k-1]`, you can sort with k rotations.
- For **reverse & rotations**:
   - For each rotation k, if `nums` matches `[k, k-1, ..., 0, n-1, ..., k+1]` (i.e., one rotation of the *reversed* array), you can sort with k rotations + 1 reverse.
- Try both directions and take the minimum.

#### **Efficient Implementation**
- For **rotations**, the match occurs if `nums[i] == (i+start)%n` for all i.
- For **reverse+rotation**, the match occurs if `nums[i] == (start-i+n)%n` for all i.

To efficiently check, find the starting index of '0' (for rotation) and starting index of 'n-1' (for rotated-reverse), and verify the pattern. This is O(n).

---

## 4. **C++ Implementation**

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minimumOperations(vector<int>& nums) {
        int n = nums.size();

        // Try forward rotation route
        int idx0 = find(nums.begin(), nums.end(), 0) - nums.begin();
        bool good = true;
        for (int i = 0; i < n; ++i) {
            if (nums[(idx0 + i) % n] != i) {
                good = false;
                break;
            }
        }
        int min_ops = good ? idx0 : INT_MAX;

        // Try reverse-rotation route
        int idxn1 = find(nums.begin(), nums.end(), n-1) - nums.begin();
        good = true;
        for (int i = 0; i < n; ++i) {
            // for reversed, after rotating left by 'idxn1', the array should be decreasing
            int pos = (idxn1 + i) % n;
            if (nums[pos] != n-1 - i) {
                good = false;
                break;
            }
        }
        if (good) min_ops = min(min_ops, idxn1 + 1); // need 1 reverse + idxn1 rotates

        return (min_ops == INT_MAX) ? -1 : min_ops;
    }
};
```

## 5. **Example Explanation**

**Example 1**:  
`nums = [0,2,1]`  
n = 3

First, check if a rotation can sort the array:

- Find idx of 0: 0 (already at start)
- Check: is nums[i] == (i+0)%3?  
  - nums[0] = 0 == 0 (good)  
  - nums[1] = 2 == 1? (No), so doesn't match.  

Try reverse+rotation path:

- Find idx of 2 (`n-1`): idx = 1  
- For each i:  
    - nums[(1+0)%3] = nums[1] = 2 == 2? Yes  
    - nums[(1+1)%3] = nums[2] = 1 == 1? Yes  
    - nums[(1+2)%3] = nums[0] = 0 == 0? Yes  
  All match.  
- So, need 1 reverse + 1 rotation ⇒ **2 moves**
