Let's tackle the LeetCode problem "**Maximum Number of K-Divisible Components**".

---

## 1. **Summary**

Given a tree where each node has a value, and an integer **k**, split the tree into the maximum number of components (by cutting edges) so that the sum of values in each component is **divisible by k**. Return that maximum number of components.

---

## 2. **Constraints & Edge Cases**

- **Tree size:** Up to 30,000 nodes; needs an O(N) solution.
- **Values:** Up to 1e9 per node.
- **k:** Arbitrary between 1 and 1e9.
- **Total sum of all nodes is divisible by k.**
- **Any set of cuts (including no cuts) is allowed, as long as the sum criterion holds for every component.**
- **Leaves and single-node components are allowed.**
- **Edge case:** If all values are divisible by k already, the best is n.
- **Smallest component: size 1 (single node).**
- **We can remove as many edges as possible, but only if it results in all subtree sums divisible by k.**

---

## 3. **Optimal Algorithm**

**Observation:**  
- Cutting an edge divides the tree into two components: the child subtree and the remaining tree.
- After cutting, **subtree sums of both parts must be divisible by k**.

**Approach:**

1. **DFS Post-order Traversal:**  
   Compute the sum of values in each subtree.

2. **Cutting Logic:**  
   - For any child (subtree) rooted at `v` of `u`,  
     if the **sum of the subtree rooted at `v` is divisible by k**,  
     we can "cut" the edge `(u, v)`, because the rest of the tree is also k-divisible  
     (since overall sum is divisible by k).
   - After cutting, that subtree becomes a component, and is no longer part of the rest of the DFS.

3. **Counting Components:**  
   - For each cut we make, the number of components increases by 1.
   - Initially, there is one component (the whole tree).
   - The answer is **number of cuts made + 1**.

4. **Implementation:**
   - During DFS, accumulate the sum of the subtree.
   - For each subtree of child, if sub_sum % k == 0, **count as a valid cut** and don't propagate its sum up.
   - Otherwise, add its sum up to the parent.

**Complexity:**  
- O(N): classic DFS traversal.
- Space: O(N) for the adjacency list and recursion stack.

---

## 4. **C++ Solution**

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    int maxKDivisibleComponents(int n, vector<vector<int>>& edges, vector<int>& values, int k) {
        vector<vector<int>> tree(n);
        for (auto& e : edges) {
            tree[e[0]].push_back(e[1]);
            tree[e[1]].push_back(e[0]);
        }

        int cuts = 0;
        function<int(int, int)> dfs = [&](int u, int parent) -> int {
            int sum = values[u];
            for (int v : tree[u]) {
                if (v == parent) continue;
                int child_sum = dfs(v, u);
                if (child_sum % k == 0) {
                    cuts++; // We can cut here
                    // Don't propagate sum up, this component stands alone
                } else {
                    sum += child_sum;
                }
            }
            return sum;
        };

        dfs(0, -1);
        // Components = cuts + 1 (the remaining super-component)
        return cuts + 1;
    }
};
```

---

## 5. **Example Explanation**

**Example 1:**  
`n = 5, edges = [[0,2],[1,2],[1,3],[2,4]], values = [1,8,1,4,4], k = 6`

Tree structure:
```
      2
     / \
    0   1
        / \
       3   4
```

- values: 0:[1], 1:[8], 2:[1], 3:[4], 4:[4]
- Removing edge (1,2):
  - Left component: 1-3: values[1] + values[3] = 8 + 4 = 12, divisible by 6
  - Right component: 0-2-4: values[0] + values[2] + values[4] = 1 + 1 + 4 = 6, divisible by 6
- No way to split into 3 or more valid parts.
- **Answer: 2**

---

### **Summary Table**

| Step                | Description                                    | Result |
|---------------------|------------------------------------------------|--------|
| DFS `/` Subtree     | Compute sum and possible cuts                  | O(N)   |
| Count cuts          | For child with %k==0, cut and +1 to `cuts`     |        |
| Final answer        | cuts + 1                                       |        |

---

**This approach ensures O(N) time, gives the maximum components in linear time, and is easily implementable.**
