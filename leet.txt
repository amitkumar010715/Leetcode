Let's break down the problem step by step:

---

## 1. **Short Summary**

Given an array of integers `nums`, a "mirror pair" is two indices `(i, j)` with `i < j` such that reversing the digits of `nums[i]` gives `nums[j]`. The task is to find the smallest possible `abs(i-j)` among all mirror pairs, or return `-1` if none exist.

---

## 2. **Constraints & Edge Cases**

**Constraints:**
- `1 <= nums.length <= 100,000` (i.e., up to 1e5 elements)
- `1 <= nums[i] <= 1,000,000,000` (all are positive, up to 1e9)

**Edge Cases:**
- No mirror pairs exist: return `-1`.
- Multiple mirror pairs: pick the pair with the smallest index distance.
- Duplicates in input: possible and allowed.
- Palindrome numbers: `reverse(nums[i]) == nums[i]` (so possible to pair with itself if such value exists later in the array).
- Each mirror pair is `(i, j)` with `i < j`, so cannot pair an index with itself.

---

## 3. **Optimal Algorithm**

**High-Level Idea:**
- For each index `j` as we traverse, check if `nums[j]` is the reverse of any earlier `nums[i]` (`i < j`).
- For all i < j, we need `reverse(nums[i]) == nums[j]`, i.e., for each `j` check if there was a prior `i` with `reverse(nums[i]) == nums[j]`.
- BUT, if we start at i and for each i store its *reverse*, then for each j, we can check if *its value* matches any prior reverse.

**Efficient Approach:**
- Traverse the array left to right.
- Use a **hash map** to store for each value `v`, the latest index `i` seen such that `reverse(nums[i]) == v`.
- For each index `j`, compute `reverse(nums[j])` and check if `nums[j]` is in the map. If so, record `abs(j - i)` for every such i < j. Since we traverse left to right, we only store the *earliest* (or latest) index for each reverse value.
- Actually, for minimum distance, keeping the *latest* index with value `reverse(nums[j])` is enough, since we're going forward.

**Steps:**

1. Initialize a hash map (`val_to_index`), mapping possible "value" → **last index**.
2. For each `j` (from 0 to n-1):
   - Compute `rev = reverse(nums[j])`
   - If `nums[j]` is in `val_to_index`, compute `abs(j - val_to_index[nums[j]])`
   - Update current minimum distance if better.
   - Set `val_to_index[rev] = j` (i.e., remember that at position `j`, we saw `rev` as a possible reverse).

**Time Complexity:** O(n), need O(1) per element (except the reverse computation, but that's only a few digits each time).

---

## 4. **Clean C++ Solution**

```cpp
#include <vector>
#include <unordered_map>
#include <limits>
#include <algorithm>

using namespace std;

class Solution {
public:
    int reverseInt(int x) {
        int rev = 0;
        while (x) {
            rev = rev * 10 + x % 10;
            x /= 10;
        }
        return rev;
    }
    
    int minimumDistance(vector<int>& nums) {
        unordered_map<int, int> val_to_index;
        int min_dist = std::numeric_limits<int>::max();
        int n = nums.size();
        
        for (int j = 0; j < n; ++j) {
            int v = nums[j];
            // If we've seen any prior i such that reverse(nums[i]) == nums[j]
            if (val_to_index.find(v) != val_to_index.end()) {
                int i = val_to_index[v];
                min_dist = min(min_dist, j - i);
            }
            // Record the index of current reverse (to match future nums[j])
            int rev = reverseInt(v);
            val_to_index[rev] = j;
        }
        
        return (min_dist == std::numeric_limits<int>::max()) ? -1 : min_dist;
    }
};
```

## 5. **Example Explanation**

**Example:** `nums = [12, 21, 45, 33, 54]`

Processing step by step:

- At j=0 (`nums[0]=12`):  
  - `reverse(12) = 21`  
  - val_to_index: {} (empty).  
  - Insert `21:0`
- At j=1 (`nums[1]=21`):  
  - `reverse(21) = 12`  
  - Does val_to_index have 21? Yes (`21:0`).  
  - So, i=0, form pair `(0,1)`, distance `1` → min_dist=1  
  - Insert `12:1`
- At j=2 (`nums[2]=45`):  
  - `reverse(45) = 54`  
  - val_to_index has 45? No.  
  - Insert `54:2`
- At j=3 (`nums[3]=33`):  
  - `reverse(33) = 33`  
  - val_to_index has 33? No.  
  - Insert `33:3`
- At j=4 (`nums[4]=54`):  
  - `reverse(54) = 45`  
  - val_to_index has 54? Yes (`54:2`).  
  - So, i=2, pair `(2,4)`, distance `2` (min_dist stays 1)  
  - Insert `45:4`

**Returns:** `1` (from the pair `(0,1)`)

---

## **Conclusion**

The optimal solution is single-pass with a hash map and digit reversal.  
**Time Complexity:** O(n); **Space Complexity:** O(n)  
This works for all edge cases.
