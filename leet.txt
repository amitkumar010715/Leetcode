Sure! Let's break down the solution step-by-step:

---

### 1. **Short Summary**
Given a string `s`, in one operation you may **sort any non-entire substring** in non-descending order. Find the minimum operations needed to fully sort `s` in non-descending order, or return **-1 if impossible**.

---

### 2. **Constraints & Edge Cases**
- **Length:** `1 < s.length <= 1e5`
- **Letters:** Only lowercase English letters.
- **You cannot sort the whole string in one operation.**
- **Edge Cases:**
  - Already sorted: answer is `0`.
  - String of length 2: only possible if already sorted (since substring can't be of length 2).
  - Impossible cases: If sorting any non-entire substring can't help (see explanation below).

---

### 3. **Optimal Algorithm & Observations**

#### **Key Insights:**
- **We can never select the entire string**: for `s` of length 2, the *only* possible substring is of length 1 (which is already sorted), so you can't change the string!
- If `s` is already sorted, `0` operations.
- **If s.length == 2:**
  - If already sorted: `0`
  - If not sorted: **no proper non-whole substring to choose (since both length-1 substrings are trivially sorted, sorting them has no effect)** → impossible, return `-1`.
- For longer strings, notice: with each operation, you can *at most* resolve a single "out-of-order" point: you can't sort the whole thing at once, so generally you'll need one operation for every segment that's "out of order".

#### **Minimal Number of Operations:**
- **Key step:** The minimum #operations is the number of times the sorted string "jumps backwards" in order compared to the original string.
- This is essentially the **number of "descending segments"** in the original string compared to the sorted version.
- More concretely:
    - Find the **length of the Longest Non-decreasing Subsequence (LNDS)** in `s`.
    - The minimum #operations is:  
      `min_operations = length(s) - LNDS`
    - Because in each operation, you can “fix” all the out-of-order elements except those already forming an increasing sequence.

#### **Why does this work?**
- Every time a character is *not* part of an increasing subsequence in `s`, it will need to be sorted/moved (via an operation, possibly fixing multiple elements at once).
- Each operation can "fix" multiple misplaced characters.

#### **Algorithm Steps:**
1. **Already sorted? Return 0.**
2. **If len(s)==2:**
    - If not sorted: return -1.
3. **Else:**
    - Compute sorted string `t = sort(s)`.
    - Find the **length of the Longest Common Subsequence (LCS)** between `s` and `t` (which will be the length of the ordered segments you don't need to fix).
    - Return `len(s) - len(LCS)`

##### **Why LCS?**
- LCS between `s` and sorted `s` tells us the **maximum number of characters already in correct order**.
- All other characters (positions) need at least one operation to fix, so `len - len(LCS)`.

- **Efficient LCS calculation:** Since string consists of lowercase letters, and `|s|` is big, use a **Patience Sorting/LNDS with coordinate compression**.

---

### 4. **Clean C++ Solution**

```cpp
#include <bits/stdc++.h>
using namespace std;

class Solution {
public:
    int minimumOperations(string s) {
        int n = s.size();
        string t = s;
        sort(t.begin(), t.end());
        if (s == t) return 0; // Already sorted

        if (n == 2) return -1; // can't sort any non-whole substring
        
        // Map each character in the sorted string to positions
        // For LCS between s and t (sorted s):
        vector<vector<int>> pos(26);
        for (int i = 0; i < n; ++i)
            pos[t[i]-'a'].push_back(i);

        vector<int> seq; // will store the positions in t as per order in s
        vector<int> idx(26, 0);
        for (int i = 0; i < n; ++i) {
            int c = s[i]-'a';
            if (idx[c] < pos[c].size()) {
                seq.push_back(pos[c][idx[c]++]);
            }
        }

        // find the length of LIS in seq
        vector<int> dp;
        for (int x : seq) {
            auto it = upper_bound(dp.begin(), dp.end(), x);
            if (it == dp.end()) dp.push_back(x);
            else *it = x;
        }
        int lcs = dp.size();
        return n - lcs;
    }
};
```
**Note:** The use of `upper_bound` in the LIS is correct for non-decreasing sequences (since characters can repeat). If only strictly increasing, use `lower_bound`.

---

### 5. **Example Explained**  
Let's use: `s = "card"`

- **Step 1:** Sorted target: `"acdr"`
- **Step 2:** LCS = "cdr" (from "card", match c, then d, then r -- but "a" from original doesn't match)
- But more formally:
    - Consider matching from left:
      - "c" matches at 0 in target.
      - "a" matches at 1.
      - "r" matches at 3.
      - "d" matches at 2.
      - LCS here is actually: "a", "d", or "a","r", etc. But the optimal LCS is of length 2 ("a","r" or "c","d"), not 3.
    - So length `n = 4`
    - Length of LCS = 2 (e.g., ("a","r"))
- **Answer:** `4 - 2 = 2`

#### Let's breakdown the actual moves:
- 1st operation: sort "car" → "acr": s = "acrd"
- 2nd operation: sort "rd" → "dr": s = "acdr" (sorted)
- **Total:** 2 operations (matches our calculated answer)!
