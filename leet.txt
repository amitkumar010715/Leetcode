Let's break down and solve the LeetCode problem **"Maximum Amount of Money Robot Can Earn"**.

---

## 1. **Summary**

- You are given an `m x n` grid with integer values (can be negative or positive).
- The robot starts at `(0,0)` and wants to reach `(m-1,n-1)`. It can only move **right** or **down**.
- At most 2 times on the path, the robot can use a **neutralization ability** to avoid the loss in a negative cell (robber).
- Find the **maximum profit** possible along a path, using optimal neutralizations.

---

## 2. **Constraints & Edge Cases**

### Constraints
- `1 <= m, n <= 500` (very large input; O(m*n) is okay, O(m*n*neutralizations) is fine as 2 is small)
- `-1000 <= coins[i][j] <= 1000`
- Robot may end with negative coins; maximization can still result in negative total.

### Edge Cases
- All cells non-negative: just sum path values.
- All cells negative: neutralize largest negatives along path.
- Neutralize *up to* 2 cells — can neutralize fewer if needed.
- Start and end positions could be negative; must handle neutralizations on start/end.

---

## 3. **Optimal Algorithm**

This is a **Dynamic Programming (DP) with State** problem.

### **State Definition**
Let:
- `dp[i][j][k]` = max profit at cell `(i,j)` having used `k` neutralizations (`k` in `0..2`).

### **Transitions**
- From `(i-1, j, k)` or `(i, j-1, k)` — previous state, not neutralizing current cell.
  - If `coins[i][j] >= 0`, always take `coins[i][j]`.
  - If `coins[i][j] < 0`:
    - Option 1: **Don't neutralize:** add `coins[i][j]` (which reduces sum).
    - Option 2: **Neutralize (if k > 0):** act as if cell had `0` value (i.e., don't subtract), pay 1 neutralization.
- For k=0, can't neutralize.
- For k=1 or 2, can choose to neutralize, but at most 2 per path.

**Initialization**: At `(0,0)`:
- If positive or 0: `dp[0][0][0] = coins[0][0]`
- If negative: 
    - `dp[0][0][0] = coins[0][0]`,
    - `dp[0][0][1] = 0` (used 1 neutralization here).

**DP Iteration**:
For each cell, for each `k` in `{0,1,2}`:
  - Possibly transition **without neutralization** (+coins[i][j]), 
  - and **with neutralizing** (if `k>0` and coins[i][j]<0: +0).

### **Complexity**
- O(m * n * 3) = 3*250,000 = 750,000 states, very acceptable.

---

## 4. **C++ Solution**

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int maximumCoins(vector<vector<int>>& coins) {
        int m = coins.size(), n = coins[0].size();
        // dp[i][j][k]: max coins at (i,j), with k neutralizations used
        vector<vector<vector<int>>> dp(m, vector<vector<int>>(n, vector<int>(3, INT_MIN)));

        // Initialization at (0,0)
        if (coins[0][0] >= 0) {
            dp[0][0][0] = coins[0][0];
        } else {
            dp[0][0][0] = coins[0][0];
            dp[0][0][1] = 0; // use 1 neutralization at start
        }

        // Fill DP table
        for (int i = 0; i < m; ++i) {
            for (int j = 0; j < n; ++j) {
                for (int k = 0; k <= 2; ++k) {
                    // Skip start cell; already initialized
                    if (i == 0 && j == 0) continue;
                    int best = INT_MIN;

                    // From top
                    if (i > 0) {
                        // Don't neutralize here
                        if (dp[i-1][j][k] != INT_MIN)
                            best = max(best, dp[i-1][j][k] + coins[i][j]);
                        // Neutralize here (if possible)
                        if (coins[i][j] < 0 && k > 0 && dp[i-1][j][k-1] != INT_MIN)
                            best = max(best, dp[i-1][j][k-1]);
                    }
                    // From left
                    if (j > 0) {
                        // Don't neutralize here
                        if (dp[i][j-1][k] != INT_MIN)
                            best = max(best, dp[i][j-1][k] + coins[i][j]);
                        // Neutralize here (if possible)
                        if (coins[i][j] < 0 && k > 0 && dp[i][j-1][k-1] != INT_MIN)
                            best = max(best, dp[i][j-1][k-1]);
                    }
                    dp[i][j][k] = best;
                }
            }
        }
        // Max over all possible neutralizations used at the end
        return max({dp[m-1][n-1][0], dp[m-1][n-1][1], dp[m-1][n-1][2]});
    }
};
```

---

## 5. **Example Explained**

**coins = [[0,1,-1], [1,-2,3], [2,-3,4]]**

Let's follow an optimal route:
- **(0,0):** `0`
- **(0,1):** `1` (now total = 1)
- **(1,1):** `-2` (*use neutralization* so no loss, total still = 1, neutralized = 1)
- **(1,2):** `3` (total = 1+3=4)
- **(2,2):** `4` (total = 4+4=8)

Thus, total coins collected = **8**.

DP tracks all possible usages of neutralizations at every cell and picks the optimal choice globally.

---

### **Summary Table**

| Cell         | Value | Option 1: Don't Neutralize | Option 2: Neutralize (if rob) |
|--------------|-------|---------------------------|-------------------------------|
| Any positive |  x    | path sum + x              | (unneeded)                    |
| Robber (<0)  | -y    | path sum - y              | path sum   (if ≤2/time left)  |

Final answer: **max over all [m-1][n-1][k]**.
