Let's address the challenge as asked:

---

## 1. **Short Summary**

Given an array `tasks` where each task requires at least `minimum` energy to start, and on completion consumes `actual` energy, what is the minimal initial energy that guarantees you can finish all tasks in *some* order?

---

## 2. **Constraints & Edge Cases**

- **Constraints:**
  - `1 <= tasks.length <= 10^5` → Must be O(N) or O(N log N).
  - `1 <= actual_i <= minimum_i <= 10^4` → Each task needs at least `minimum_i` energy to start and reduces energy by `actual_i` on completion.
- **Edge Cases:**
  - Only one task: Just need at least `minimum` energy (the task's required minimum).
  - All tasks have actual == minimum: Their order doesn't matter.
  - Some tasks are "cheap" (actual ≪ minimum), others "expensive".
  - The order can dramatically affect the minimum initial energy.
---

## 3. **Optimal Algorithm**

### **Key Idea**
- You can do tasks in any order.
- For each task: Before starting, your energy >= `minimum_i`.  
  After finishing: energy decreases by `actual_i`.
- *If you do tasks with the biggest gap between `minimum_i` and `actual_i` first, you minimize the "wasted" energy you must keep as a buffer.*

### **Approach**
1. **Sort tasks** by decreasing order of `minimum_i - actual_i` (`difference`).  
   - Intuitively: Tasks that require a lot of "buffer" (i.e., where minimum ≫ actual) should be done first so later, when you have less energy, the remaining tasks can still be started.
2. **Process in that order**, simulating from some starting energy, but instead of trying each value, let's invert the process:
   - Work backwards by **calculating the minimal initial energy** needed to do all tasks in the sorted order:
   - Start from the end, set initial energy at 0, process from last to first (reverse).
   - At each task, to ensure you can start this task with the energy you will have at that step, the *energy just before this task* must be at least `minimum_i`, but then after this task we will have spent `actual_i` energy, so add it back.
   - Recurrence:  
     ```
     initial_energy = max(minimum_i, initial_energy + actual_i)
     ```
     (Do in reverse order).

### **Why this Works**
- Sorting by `minimum_i - actual_i` is a *known greedy*, proved by observing that if you do a "buffer-needy" task late, you may not be able to finish it (since your remaining energy will be too low!).

---

## 4. **Clean C++ Solution**

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int minimumEffort(vector<vector<int>>& tasks) {
        // Sort in decreasing order of (minimum - actual)
        sort(tasks.begin(), tasks.end(), [](const vector<int>& a, const vector<int>& b) {
            // stronger need for early: bigger (minimum-actual)
            return (a[1] - a[0]) > (b[1] - b[0]);
        });

        int energy = 0;
        // Process in reverse: start from last, work to front
        for (const auto& task : tasks) {
            // At this task, we must have at least minimum to start,
            // and after we finish, energy -= actual, so before, must have
            // either minimum or enough to cover remainder
            energy = max(task[1], energy + task[0]);
        }
        return energy;
    }
};
```

---

## 5. **Example Explanation**

Let's use **Example 1:**

> `tasks = [[1,2],[2,4],[4,8]]`

**Step 1: Sort by (minimum-actual) decreasing:**  
- [4,8]: 8-4=4  
- [2,4]: 4-2=2  
- [1,2]: 2-1=1  
So sorted: `[[4,8],[2,4],[1,2]]`

**Step 2: Compute minimal initial energy backward:**
- Start with energy = 0
- Last task: [1,2]
    - `energy = max(2, 0+1) = 2`
- Second: [2,4]
    - `energy = max(4, 2+2) = 4`
- First: [4,8]
    - `energy = max(8, 4+4) = 8`

**So, minimum required initial energy = 8**

**Order:** Do [4,8](spend 4, remain 4), then [2,4](spend 2, remain 2), then [1,2](spend 1, remain 1).
This matches the problem's sample output and explanation.

---

### **Summary Table**

| Step        | Task   | Energy Needed Before | Energy After  |
|-------------|--------|---------------------|---------------|
| Start       |        |         8           |      8        |
| Task 3 [4,8]|        |       >=8           | 8-4=4         |
| Task 2 [2,4]|        |       >=4           | 4-2=2         |
| Task 1 [1,2]|        |       >=2           | 2-1=1         |

---

## **In summary**
- Sort by `(minimum - actual)` descending.
- Process with greedy recurrence: `energy = max(minimum, energy + actual)`.
- Time: O(N log N), Space: O(1) extra (besides sort).
