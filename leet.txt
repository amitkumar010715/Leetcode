## 1. **Short Summary**

Given a rotated sorted array of **unique** integers, we are to find the minimal element in **O(log n)** time. The array is sorted in ascending order, then rotated between 1 and n times.

---

## 2. **Constraints & Edge Cases**

**Constraints:**
- `1 <= n <= 5000`
- Each `nums[i]` is unique and in `[-5000, 5000]`.
- The array is a rotated (by any value between 1 and n) version of sorted order.

**Edge Cases:**
- Minimal case: single element (`nums=[x]`, answer is `x`).
- No actual rotation (rotated n times, so array is still sorted).
- Rotated such that the minimum is at the last position.
- Rotated such that the minimum is at the middle.
- Note: array is never empty and never contains duplicates.

---

## 3. **Optimal Algorithm**

### Approach: Binary Search

We use a binary search to locate the pivot (where order breaks, or, in this context, the minimum element):

Let:
- `l` = 0 (start index)
- `r` = n-1 (end index)

**Binary Search Steps:**
- While `l < r`:
    - Compute `mid = l + (r-l)/2`
    - If `nums[mid] > nums[r]`, this means the minimum is to the right of `mid` (excluding `mid`), so set `l = mid + 1`.
    - Else, the minimum is at `mid` or to its left, so set `r = mid`.
- After the loop, `l` (or `r`) will point to the minimal element.

**Why?**
The property being exploited is: in a rotated sorted array, the minimal element is the only place where the next element is smaller than the previous, and when you compare `nums[mid]` and `nums[r]`:
- If `nums[mid] > nums[r]`, the minimum lies in the right subarray.
- Else, the minimum lies in the left (including `mid`).

**Time Complexity:**\
O(log n) due to binary search.

---

## 4. **C++ Solution**

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int l = 0, r = nums.size() - 1;
        while (l < r) {
            int mid = l + (r - l) / 2;
            if (nums[mid] > nums[r]) {
                // Minimum must be to the right of mid
                l = mid + 1;
            } else {
                // Minimum is at mid or to the left
                r = mid;
            }
        }
        return nums[l]; // or nums[r], since l == r
    }
};
```

---

## 5. **Explain One Example**

**Example:**  
`nums = [4, 5, 6, 7, 0, 1, 2]`

Let's trace:

```
l = 0, r = 6
mid = (0 + 6) / 2 = 3, nums[3] = 7 
Compare nums[3] (7) > nums[6] (2) : true => l = mid + 1 = 4

l = 4, r = 6
mid = (4 + 6) / 2 = 5, nums[5] = 1
Compare nums[5] (1) > nums[6] (2) : false => r = mid = 5

l = 4, r = 5
mid = (4 + 5) / 2 = 4, nums[4] = 0
Compare nums[4] (0) > nums[5] (1) : false => r = mid = 4

l = 4, r = 4
Stop; minimal element is nums[4] = **0**
```

---

**Summary**:  
- Use binary search, compare `mid` and `r` to determine which half contains the minimum.
- Loop until `l == r`, then return `nums[l]`.  
- Time: O(log n).  
- Works for all rotation amounts, including no rotation and all-n rotations.
