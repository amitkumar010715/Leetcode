Let's address your problem in a detailed, structured manner:

---

## 1. **Summary**

Given a range `[num1, num2]`, the *waviness* of a number is the count of its *peaks* and *valleys* (middle digits that are strictly greater/less than neighbors). For each number in the range, sum the waviness. Return this total.

- **Peaks**: digit is strictly greater than both neighbors.
- **Valleys**: digit is strictly less than both neighbors.
- *First and last digits cannot be peaks or valleys.*
- *Numbers with < 3 digits cannot have any peak or valley.*

---

## 2. **Constraints & Edge Cases**

- `1 <= num1 <= num2 <= 10^15` (up to 15 digits!)
- Number range can have up to `10^15` numbers—brute force per number is infeasible.
- Numbers with less than 3 digits → automatically contribute 0.
- Inputs may be of varying digit lengths.
- Leading zeros are not possible due to integer constraints.
- For large ranges, efficient digit DP is implied.

---

## 3. **Optimal Algorithm**

### **Observations**
- Need to compute the sum efficiently for potentially huge ranges.
- Can use **digit DP** (dynamic programming by digits), as in "count how many numbers in a range have certain properties."

#### **DP State**
When processing digits, at each position, we have:
- Current position (`pos`) from most to least significant digit,
- Last two digits (`d1`, `d2`), required to determine if a peak or valley happens at current digit,
- Tightness (are we still matching the prefix of the bound?),
- Whether we're on a leading zero (in our context, always false after first position unless we're padding).

#### **DP Choice**
- At each digit, iterate over possible choices for current digit within allowed tightness bounds.
- Build number left-to-right, updating D1/D2 (prev/prevprev).
- If we have at least three digits, at each step check if last digit is a peak/valley (using d2, d1, current digit).
- The goal is: for every number, sum up its waviness.

#### **How is DP Used?**
- For each bound (from `0` to `X`), digit DP gives the *sum of waviness* over all numbers ≤ `X`.
- Get answer for `[num1, num2]` by calculating `f(num2) - f(num1-1)`.

### **Plan**
1. Write digit DP to compute total waviness for `<= bound` for a given upper-bound number as string.
2. Use it for `num2` and `num1-1`.
3. Take the difference.

#### **Key Subtleties**
- Carefully manage transitions for tight bounds.
- "num1 - 1" must be handled carefully for big integers.

---

## 4. **C++ Solution**

```cpp
#include <bits/stdc++.h>
using namespace std;

// DP cache: pos, last2, last1, tight, leading_zero
// We use -1 for undefined last1/last2 (i.e., for first digits)
typedef long long ll;

class Solution {
public:
    string toStr(ll n) {
        return to_string(n);
    }

    // DP: pos, prevprev, prev, tight, leading_zero
    ll dp[16][11][11][2][2];
    string s;

    ll dfs(int pos, int prevprev, int prev, bool tight, bool leading_zero) {
        if (pos == s.size()) 
            return 0;
        if (dp[pos][prevprev+1][prev+1][tight][leading_zero] != -1)
            return dp[pos][prevprev+1][prev+1][tight][leading_zero];
        ll res = 0;
        int mx_digit = tight ? (s[pos] - '0') : 9;
        for (int d = 0; d <= mx_digit; ++d) {
            bool next_tight = tight && (d == mx_digit);
            bool next_leading_zero = leading_zero && (d == 0);
            int npp = prev, np = d;
            ll add = 0;
            // Only compute peaks/valleys if we have at least prevprev, prev, d as actual digits
            // Leading zeros are not part of the actual number
            if (!leading_zero && pos >= 2) {
                // prevprev, prev, d
                if (prev > prevprev && prev > d) add = 1; // peak at prev
                if (prev < prevprev && prev < d) add = 1; // valley at prev
            }
            // For numbers with at least 3 digits, *not in leading zeros*
            res += add + dfs(pos+1, npp, np, next_tight, next_leading_zero);
        }
        return dp[pos][prevprev+1][prev+1][tight][leading_zero] = res;
    }

    // f(x): total waviness over all numbers <= x
    ll f(string x) {
        s = x;
        memset(dp, -1, sizeof(dp));
        return dfs(0, -1, -1, 1, 1);
    }

    int totalWavinessInRange(long long num1, long long num2) {
        auto decStr = [](string s) {
            int n = s.size();
            int i = n-1;
            while (i >= 0 && s[i] == '0') {
                s[i] = '9';
                i--;
            }
            if (i == -1) return string("0"); // special case: "0" - "1" = "0"
            s[i]--;
            if (s[0] == '0') s = s.substr(1);
            return s;
        };
        ll res2 = f(toStr(num2));
        ll res1 = num1 > 1 ? f(decStr(toStr(num1))) : 0;
        return res2 - res1;
    }
};
```

## 5. **Step-by-step Example**

Let's explain **Example 1**: `num1 = 120, num2 = 130`.

We enumerate numbers 120, 121, ..., 130.

We check each one's middle digit (since all are 3-digits):

- 120: digits 1 2 0. Middle digit 2 is a peak (2 > 1 and 2 > 0) → waviness = 1.
- 121: digits 1 2 1. 2 > 1 and 2 > 1, but not strictly, so no peak. But actually: 2 == 1 for both sides, so not peak/valley.
- 122: 1 2 2. 2 > 1 but not 2 > 2 (equal to right), so not a peak.
- 123: 1 2 3. 2 > 1, not 2 > 3; not a peak/valley.
- ...
- 130: 1 3 0. 3 > 1 and 3 > 0 → peak at digit 3, waviness = 1.

If you go through, only:
- 120: waviness 1
- 121: waviness 1 (wait, this seems inconsistent with the earlier output? Let's check the peak/valley definition!)
- 122~129, only 130 counts as peak.

Careful: **"strictly greater than both neighbors"**.
- 121: 2 == 1 at right, so not peak.

So the correct ones are:
- 120: 2 > 1, 2 > 0 ✔
- 130: 3 > 1, 3 > 0 ✔

But the example says **3** in total and includes 121. That suggests the definition accepts equality in neighbors, but the **problem says strictly**.

Let's check example block:

> 121: middle digit 2 is a peak, waviness = 1.

So for 121 (1 2 1): 2 > 1, 2 > 1. But since both neighbors are equal and 2 > 1, it counts as a peak.

So, yes, we have coded accordingly: 2 > 1 (strictly), and 2 > 1 (strictly), so even if they're equal to each other, as long as center digit is greater than both, it's a peak.

Therefore, the code above handles this correctly!

**Output:** 120 (waviness=1), 121 (waviness=1), 130 (waviness=1), sum=3.

## **Conclusion**

The optimal approach is **digit DP**.  
- This efficiently computes, in O(D^4 * 2 * 2), where D ≤ 15.
- Handles even huge intervals up to 10^15.
- Subtracting prefix sum values for `num2` and `num1-1` gives the answer.
