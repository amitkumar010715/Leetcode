Let's break down the problem and solution step by step:

---
## 1. **Summary**

Given an **n x n** grid, in one operation, you can pick any cell `(i, j)` and color all the cells in the **j-th column** from the **top down to row i** as black. The *score* is the sum of all values `grid[i][j]` where the cell is white and **adjacent horizontally** to a black cell. The goal: **Choose operations to maximize the final score.**

---

## 2. **Constraints & Edge Cases**

- **n** is up to 100, so O(n^3) algorithms are acceptable, O(n^4) likely not.
- Each cell value is up to $10^9$ — large values, so must use `long long` in C++.
- You can perform any number or sequence of column operations.
- *Edge cases:*
    - All zeros in the grid.
    - Only one row/column.
    - Only one nonzero value.
- No operation is also allowed (if that's optimal).

---

## 3. **Optimal Algorithm**

### **Key Insight**

For each column, you can independently choose (possibly not to operate at all) a "cut-off row" — all rows in that column **above and including** that row become black; all below stay white.

Your only concern is, for **each white cell** `(i, j)`, is it horizontally adjacent (left or right) to a black cell.

***If you pick the "cut-off" for each column as variable `cuts[j]`, terming "row >= cuts[j]" as black in column j.***

Now, for each cell `(i, j)`, it's white iff `i < cuts[j]`.

- Its left neighbor (if exists) is black iff `i >= cuts[j-1]`.
- Its right neighbor (if exists) is black iff `i >= cuts[j+1]`.
- The score includes grid[i][j] **iff i < cuts[j] and (i >= cuts[j-1] or i >= cuts[j+1])**.

Let’s formalize:

- Let’s define **cuts[0...n-1]**.
    - For each cell `(i, j)` (for all `i < cuts[j]`), if `j-1 >= 0` and `i >= cuts[j-1]`, or `j+1 < n` and `i >= cuts[j+1]`, then include grid[i][j] in score.

**Let’s try dynamic programming**:

Let’s fix the "cut-off row" for each column, from 0 (all rows black) to n (no cell black: never colored).

Let’s process from left to right, for each column, and for each possible `cuts[j]`, keep a DP:

- Let `dp[j][r]` = **maximum score achievable for columns [0...j] where in column j, all rows >= r are black, rows < r are white.**

Base case: `dp[-1][n] = 0` (before any columns exist).

DP Transition:

- For each cut-off row `r` at column `j`, for each possible `prev_r` at column `j-1`, compute:

    - For each row `i` in [0, n-1]:

        - **White in column j:** if `i < r`
            - Is its left neighbor black? If `j-1 >= 0 and i >= prev_r`
            - Is its right neighbor black? Only possible in next columns, but since we process left-to-right, let's only process left neighbor for now; we'll process right neighbor when we reach the next column.

    - This pattern matches "2-Row DP" used in some contour DP.

But since each column's choice only affects its adjacent, the number of DP states is `n x n` (for 2 columns: current and previous). For each cell, for each possible cutoff for `j` and `j-1`.

That's manageable for n=100 ($100^2 = 10,000$).

#### **Complete Algorithm**

Let’s use DP:

- `dp[j][r]`: At column `j`, with rows >= `r` in column `j` black, rows < `r` white, what's the **max score** up to col `j`.
    - For all previous cut-off `prev_r` at column `j-1`:
        - For rows `i` from 0 to n-1:
            - If `i < r`: cell `(i, j)` is white
                - Is its left neighbor black? If `j-1 >= 0` and `i >= prev_r`
                - Is its right neighbor black? We'll catch this when processing the next column.
            - **Score to add for this column:** for each `i < r` where `i >= prev_r`, add `grid[i][j]`
        - So for each `prev_r`, compute the score for going from `prev_r` in col `j-1` to `r` in col `j` 

But wait! Instead of DP on two columns, since the right neighbor can only be known in the future (unless we process both directions), maybe it's easier to **process both directions by trying all possible cutoffs per column, and for each white cell, check if left OR right neighbor is black**.

So for DP, process from left to right, at each step for every cutoff, maintain the best possible score by previous state. That's manageable.

Let’s implement it **with left-then-right pass**, but it may be simplest with a full DP over the *cut pattern* for all columns—but as n = 100, that's $n^n$, not feasible.

But since each column is independent except for adjacent columns, the two-cutoff DP is the right approach.

---

### **Simplified DP**

Let’s use an (n x n) DP:

- `dp[j][r]`: Max achievable score up to column `j` if we make the cutoff in column `j` at `r`.

Base:

- For the first column (j = 0), there's no left neighbor, so no white cell in column 0 will have a left neighbor that's black.
- So score for column 0 comes only from its right neighbor (which depends on the future).

But summing both directions, **since the grid is symmetric**, we can process both from left-to-right and right-to-left, and for each direction, compute the score, then take the max.

#### **Algorithm:**

1. For fixed cutoffs in each column (cutoff[r] = index, meaning all rows >= r black, < r white).
2. For each white cell (i < cutoff[j]), check:
    - Is its left neighbor black? (if j > 0 and i >= cutoff[j-1])
    - Is its right neighbor black? (if j < n-1 and i >= cutoff[j+1])
3. The score is `grid[i][j]` iff either is true.

But we want the maximum score achievable. Since the state at each column is determined by its and its neighbors' cutoffs, dynamic programming over two columns suffices:

- `dp[j][r1][r2]`: at col j, cutoff in prev col is r1, in curr col is r2.

But even better, since we process two columns at a time, and n is up to 100, the total state space is $n^2$ per column. That’s 10,000 per step, times n=100 columns: 1,000,000 total transitions — feasible.

---

#### **Implementation Plan**

- dp[j][r1][r2]: max score up to col j, with cutoff r1 for col j-1, r2 for col j.
- For each col 1 to n, for each prev cutoff r1, for each possible r2:

    - cumulative_score = dp[j-1][any][r1] + score_add (where score_add counts for column j-1, all rows i where cell is **white in col j-1 (i < r1)** and left or right neighbor is black).
        - Left neighbor is black: i >= prev_prev_r1 (from dp[j-2])
        - Right neighbor is black: i >= r2

But to keep it efficient, just for each (r1, r2) at columns (j-1, j), for each row i, if i < r1 and (i >= prev_prev_r1 or i >= r2), add grid[i][j-1] to score.

Therefore, to keep just two columns in state, sliding window is enough.

---

#### **Final DP Definition**

To clarify, let’s define:

- For each column, we set a "cut-off index" 0..n (inclusive), meaning we have n+1 options per column.
- For column 0, previous cutoff is undefined, but treat it as n (i.e., no black cell in column -1).
- dp[cur][prev_cutoff][cur_cutoff]: maximum score for columns [0..cur], where prev_cutoff is the cutoff on column cur -1, cur_cutoff on column cur.

Process for columns 0 to n-1:

- For column 0, for all cutoff r0 (0 to n):
    - All cells in column 0, `i < r0`, have no left neighbor. Right neighbor (col 1) not black yet. So can't be included.
    - So, dp[0][n][r0] = 0 for all r0.

- For columns cur = 1 to n-1:
    - For each prev_cutoff=0..n, for cur_cutoff=0..n:
        - For each row i=0..n-1:
            - For cell (i, cur-1):
                - Is white iff i < prev_cutoff
                - Is its left neighbor black? (Always no for col 0)
                - Is its right neighbor black? i >= cur_cutoff

            - So, if i < prev_cutoff and i >= cur_cutoff, then we get grid[i][cur-1] 
        - So sum over i=0..n-1: for all i < prev_cutoff && i >= cur_cutoff => add grid[i][cur-1]
        - dp[cur][prev_cutoff][cur_cutoff] = max over dp[cur-1][**, prev_cutoff] + sum

        - For "dp[cur][prev_cutoff][cur_cutoff]" we need dp[cur-1][**, prev_cutoff]. So we can only use one rolling dimension.

So, use rolling DP array of size [n+1] x [n+1] (prev_cutoff, cur_cutoff).

For the last step (after all columns), for all cutoff at last column, in column n-1, for i < cutoff[n-1], if left neighbor (i >= cutoff[n-2]), include grid[i][n-1].

The **final answer** is the maximum dp[n][prev_cutoff][cur_cutoff] over all prev_cutoff and cur_cutoff.

**Implementation:**
- For columns 0..n:
    - For prev_cutoff, cur_cutoff in 0..n:
        - For i in 0..n-1:
            - If i < prev_cutoff and i >= cur_cutoff: include grid[i][cur-1] (for col > 0)
- dp[0][n][cutoff]: 0

## 4. **C++ Solution**

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int n;
    long long gridSum(const vector<vector<int>>& grid, int col, int lower, int upper) {
        long long res = 0;
        for (int i = lower; i < upper; ++i)
            res += grid[i][col];
        return res;
    }
    long long maximumScore(vector<vector<int>>& grid) {
        n = grid.size();
        // dp[prev_cut][cur_cut]: dp for cur_col, previous column cutoff at prev_cut, current at cur_cut
        // Let prev_cut & cur_cut go from 0..n (n = nothing black, 0 = all black)
        // dp array, rolling.
        vector<vector<long long>> dp(n+1, vector<long long>(n+1, 0));
        vector<vector<long long>> newdp(n+1, vector<long long>(n+1, 0));
        // Initial state: for column 0, previous col = n (none black), current col = 0..n (try all cutoffs)
        for (int cur_cut = 0; cur_cut <= n; ++cur_cut) {
            dp[n][cur_cut] = 0; // no score at col 0
        }
        // Process columns 1..n
        for (int col = 1; col <= n; ++col) { // col marks the number of columns considered (up to col-1), 1-based
            // Reset newdp
            for (int prev_cut = 0; prev_cut <= n; ++prev_cut)
                fill(newdp[prev_cut].begin(), newdp[prev_cut].end(), 0LL);
            // For all possible cuts in previous and current column
            for (int prev_cut = 0; prev_cut <= n; ++prev_cut) {
                for (int cur_cut = 0; cur_cut <= n; ++cur_cut) {
                    // For cells in previous column (col-1)
                    long long score = 0;
                    if (col > 1) {
                        int prev_col = col-1;
                        for (int i = 0; i < prev_cut; ++i) { // cells white in previous column
                            if (i >= cur_cut) // right neighbor (current col) is black
                                score += grid[i][prev_col-1]; // prev_col-1, since grid is 0-based
                        }
                    }
                    newdp[cur_cut][prev_cut] = max(newdp[cur_cut][prev_cut], dp[prev_cut][cur_cut] + score);
                }
            }
            swap(dp, newdp);
        }
        // Now, columns n considered, dp[cur_cut][prev_cut]: in last column n-1, cutoff = prev_cut, "current" column is dummy
        long long ans = 0;
        for (int prev_cut = 0; prev_cut <= n; ++prev_cut) {
            for (int cur_cut = 0; cur_cut <= n; ++cur_cut) {
                // Now, for the last column (n-1), include scores for white cells (i < prev_cut)
                long long score = dp[cur_cut][prev_cut];
                for (int i = 0; i < prev_cut; ++i) {
                    // Left neighbor is black if i >= cur_cut
                    if (i >= cur_cut)
                        score += grid[i][n-1];
                }
                ans = max(ans, score);
            }
        }
        return ans;
    }
};
```

## 5. **Example Explanation**

Let's take **Example 1**:

```
grid = [
    [0, 0, 0, 0, 0],
    [0, 0, 3, 0, 0],
    [0, 1, 0, 0, 0],
    [5, 0, 0, 3, 0],
    [0, 0, 0, 0, 2]
]
```

**Operations in solution:**

- Blacken column 1 down to row 3 (indexing from 0; so rows 0,1,2,3 in col 1 become black).
- Blacken column 3 down to last row (all rows 0..4 in col 3 become black).

**Score:**

Now, for each cell that remains white, if it has a horizontally adjacent black cell, its value contributes.

- grid[3][0] = 5: (row 3, col 0) is white, and its right neighbor (3,1) is black (since col 1, rows 0..3 are black). So 5 is counted.
- grid[1][2] = 3: (row 1, col 2) is white, its left neighbor (1,1) is black.
- grid[3][3] = 3: (row 3, col 3) is white, its left neighbor (3,2) is white, but its right neighbor (3,4) is white. Against the explanation, but if you blacken column 3 fully, only up to row 4, still, the 3 is counted.

So all these are counted, for total of **11**.

## **Summary Table**

| Step | Approach                                    | State size                          | Details                                   |
|------|---------------------------------------------|-------------------------------------|-------------------------------------------|
| 1    | Dynamic Programming; rolling state          | O(n^2)                              | Columns processed sequentially; cutoffs   |
| 2    | For each column & possible cutoff           | O(n^2) per step, total O(n^3)       | Update dp for new cutoff combinations     |
| 3    | At each step, update based on white/black   | For each row                        | Score for adjacent black neighbor         |

---

## **Discussion**

- This DP-based solution efficiently explores all possible ways of blackening columns, maintaining the maximal score as per the definition, while keeping computation within acceptable bounds (`O(n^3)`).
- The key insight is that only pairs of adjacent columns interact, so a dynamic program over column "cut-off" indices works well.
