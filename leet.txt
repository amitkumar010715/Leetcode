Let's solve the LeetCode problem **"Find Unique Binary String"** in depth.

---

## 1. **Short Summary**

Given an array `nums` containing all unique binary strings of length `n` except one, find **any** binary string of length `n` that does **not** appear in `nums`.

---

## 2. **Constraints & Edge Cases**

- `n == nums.length` (Each string is of length `n`, and there are `n` strings.)
- Each string only contains `'0'` or `'1'`.
- All strings in `nums` are unique.
- `1 ≤ n ≤ 16` (So, brute-force over at most 65536 options is possible.)
- **Edge Case:**  
  - `n = 1` → nums = ["0"] or ["1"]  
  - `nums` does NOT contain all possible strings (it's missing one, since there are `n` strings but `2^n` is always > n for n>1).

---

## 3. **Optimal Algorithm**

### **Insight**

- There are `n` strings of length `n` but `2^n` _possible_ unique binary strings of length `n`.
- One way: generate all possible strings, return the first not in `nums`. _But O(2^n)_.
- **Smarter way:** Use the "diagonalization" method (Cantor's diagonal argument).

### **Diagonalization Reasoning**

Let’s construct a new string where, for `i`-th position, `ans[i]` is the **opposite bit** of `nums[i][i]`.  
This guarantees that the resulting string will **differ from each input string in at least one position** (the i-th character of the i-th string), so it cannot be included in `nums`.

### **Algorithm (Steps)**

1. For `i = 0 to n-1`:
   - If `nums[i][i] == '0'`, set `ans[i] = '1'`
   - Else, `ans[i] = '0'`

2. Return the resulting string.

- **Time Complexity:** O(n)

---

## 4. **Clean C++ Solution**

```cpp
class Solution {
public:
    string findDifferentBinaryString(vector<string>& nums) {
        int n = nums.size();
        string ans(n, '0');
        for (int i = 0; i < n; ++i) {
            ans[i] = nums[i][i] == '0' ? '1' : '0';
        }
        return ans;
    }
};
```

---

## 5. **Example Walkthrough**

**Example:**  
`nums = ["111", "011", "001"]`

- Step by step:
  - For `i = 0`: `nums[0][0] = '1'` ⇒ `ans[0] = '0'`
  - For `i = 1`: `nums[1][1] = '1'` ⇒ `ans[1] = '0'`
  - For `i = 2`: `nums[2][2] = '1'` ⇒ `ans[2] = '0'`
- So, **ans = "000"**
- Is "000" in `nums`? No! So it's a valid answer.

You could also return "101", "010", etc. — the diagonalization guarantees at least one valid answer.

---

**In summary:**  
We construct an answer that differs from the i-th string in the i-th position.  
This O(n) diagonalization is correct, simple, and always works!
