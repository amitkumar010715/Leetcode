### 1. Short Summary

Given an array of integers, find the **length** of the **longest contiguous subarray** such that the number of **distinct even numbers** equals the number of **distinct odd numbers** in that subarray.

---

### 2. Constraints & Edge Cases

- **Constraints:**
  - `1 <= nums.length <= 10^5` (must be `O(n)~O(n log n)`).
  - `1 <= nums[i] <= 10^5`
- **Edge Cases:**
  - All numbers are even/odd: No balanced subarray except possibly 0-length.
  - All numbers are unique vs. many repetitions.
  - Repeated even or odd numbers (only distinct count matters).
  - Minimal input: length 1.

---

### 3. Optimal Algorithm

#### **Key Observations:**
- We need a subarray where `count_distinct_even == count_distinct_odd`.
- As we slide through the array, tracking the **current sets** of distinct even and odd numbers in a window would be too slow (`O(n^2)`).
- The main challenge is handling "distinct count" efficiently.

#### **Algorithm: Hashing with Prefix Mapping**

**Core Idea:**  
- Let `delta = (# distinct even seen so far) - (# distinct odd seen so far)` at each prefix.
- For each prefix position, record the *first* position where a given `delta` occurs.
- When `delta` is the same at two positions `(l, r)`, it means the number of new distinct evens and odds between positions `(l+1) ... r` are equal.
- To support this, we incrementally track two sets (`seen_even` and `seen_odd`) as we process the array.

#### **Detailed Steps:**
1. Initialize two sets: `seen_even`, `seen_odd`.
2. Initialize a map `delta_to_index` with `{0: -1}` (delta `0` first seen before start).
3. For each index `i` in `nums`:
   - If `nums[i]` is **even** and not in `seen_even`: add to `seen_even`
   - If `nums[i]` is **odd** and not in `seen_odd`: add to `seen_odd`
   - Compute `delta = seen_even.size() - seen_odd.size()`
   - If `delta` previously seen at position `j`, `nums[j+1 .. i]` is candidate.
     - Update answer with `i-j`
   - Else, record `delta` and its first occurrence at index `i`
4. Return the max length found.

**Time complexity:**  
- Each number only enters `seen_even` or `seen_odd` **once**: O(n)
- Map lookups and sets: O(1) average.
- So overall O(n)

---

### 4. Clean C++ Solution

```cpp
#include <vector>
#include <unordered_set>
#include <unordered_map>
using namespace std;

class Solution {
public:
    int longestBalancedSubarray(vector<int>& nums) {
        unordered_set<int> seen_even, seen_odd;
        unordered_map<int, int> delta_to_index;
        delta_to_index[0] = -1;  // prefix before start
        int maxlen = 0;
        int delta = 0;
        for (int i = 0; i < nums.size(); ++i) {
            int x = nums[i];
            if ((x % 2) == 0) {
                // even
                if (seen_even.insert(x).second) { // first time seen
                    delta += 1;
                }
            } else {
                // odd
                if (seen_odd.insert(x).second) {
                    delta -= 1;
                }
            }
            if (delta_to_index.count(delta)) {
                // The subarray between previous occurrence+1 and i is balanced
                int len = i - delta_to_index[delta];
                if (len > maxlen) maxlen = len;
            } else {
                delta_to_index[delta] = i;
            }
        }
        return maxlen;
    }
};
```

### 5. Example Explanation

#### Example:  
`nums = [3,2,2,5,4]`

Let's walk through:

- Index 0, nums[0]=3 (odd): seen_odd = {3}, delta=-1  
- `delta_to_index[-1]=0`
- Index 1, nums[1]=2 (even): seen_even={2}, delta=0
- `delta_to_index[0]=-1` → delta 0 seen at -1 → subarray [0..1], len=2
- Index 2, nums[2]=2 (even): 2 already in seen_even → delta unchanged  
- Still, `delta_to_index[0]=-1` → subarray [0..2], len=3
- Index 3, nums[3]=5 (odd): seen_odd={3,5}, delta=-1  
- `delta_to_index[-1]=0` → subarray [1..3], len=3
- Index 4, nums[4]=4 (even): seen_even={2,4}, delta=0
- `delta_to_index[0]=-1` → subarray [0..4], len=5

**Maximum is 5** (`[3,2,2,5,4]`), as required.

---

**Summary:**  
- Use a difference variable for distinct evens vs. odds.
- Map each difference to its first occurrence index.
- Sets to track which unique evens/odds have been seen so far.
- For every prefix, the answer is the largest window where the difference hasn't changed.  
- Complexity O(n), passes all constraints.
