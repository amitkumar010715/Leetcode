## 1. **Short Summary**

Given an integer `n`, count how many numbers in the range `[1, n]` are "good"—meaning all digits are valid when rotated 180 degrees **and** the entire number changes to a different value after that rotation.

- Valid rotations:
  - `0, 1, 8` → themselves (not "good" as no change)
  - `2 ↔ 5`, `6 ↔ 9`
- Digits `3, 4, 7` make a number invalid because they're not valid upon rotation.

---

## 2. **Constraints & Edge Cases**

- **Constraints**:
  - `1 <= n <= 10^4` (so a brute-force check for all numbers up to n is efficient)
- **Edge Cases**:
  - Numbers that contain only `0, 1, 8` are valid after rotation but are **not "good"** (unchanged).
  - Numbers containing `3, 4, 7` are invalid.
  - Only numbers with at least one of `2, 5, 6, 9` and all other digits valid are "good".

---

## 3. **Optimal Algorithm**

- For each number from `1` to `n`:
  1. Check all digits:
     - If contains `3, 4, 7` → skip (invalid).
  2. Check if at least one digit is `2, 5, 6, 9` (so the rotated number is **different** from the original).
  3. If both above, increment the count.

This brute-force approach is optimal given the constraint (`n` up to 10000).

---

## 4. **Clean C++ Solution**

```cpp
class Solution {
public:
    int rotatedDigits(int n) {
        int count = 0;
        for (int i = 1; i <= n; ++i) {
            bool valid = true, changed = false;
            int num = i;
            while (num > 0) {
                int d = num % 10;
                if (d == 3 || d == 4 || d == 7) {
                    valid = false;
                    break;
                }
                if (d == 2 || d == 5 || d == 6 || d == 9)
                    changed = true;
                num /= 10;
            }
            if (valid && changed)
                ++count;
        }
        return count;
    }
};
```

## 5. **Example Explained**

Take `n = 10`.

Let's check each `i` in `1..10`:

|  i  | Digits | Valid after rotate? | Changes? | Good? |
|:---:|:------:|:------------------:|:-------:|:-----:|
|  1  |   1    |  yes (1→1)         | no      |   no  |
|  2  |   2    |  yes (2→5)         | yes     |  yes  |
|  3  |   3    |      no            |         |   no  |
|  4  |   4    |      no            |         |   no  |
|  5  |   5    |  yes (5→2)         | yes     |  yes  |
|  6  |   6    |  yes (6→9)         | yes     |  yes  |
|  7  |   7    |      no            |         |   no  |
|  8  |   8    |  yes (8→8)         | no      |   no  |
|  9  |   9    |  yes (9→6)         | yes     |  yes  |
| 10  | 1,0    |  yes (1→1, 0→0)    | no      |   no  |

So "good" numbers are **2, 5, 6, 9**, total = **4**.

- **Valid after rotation?**: All digits must be in {0,1,2,5,6,8,9}
- **Changes?**: At least one digit in {2,5,6,9}
- Only then, the number is "good".
